## Required correction

### ALV-007-C02-R01-01 — Timeline source links are inaccessible to billing-only readers

The item requires the account timeline to link financial effects back to source completed care, while the timeline itself is intentionally authorized by ViewBilling. The implementation renders every completed-procedure source as a hard-coded Clinical history link to /patients/{patientId}/history. A role allowed to read billing but without clinical-documentation access therefore receives a link it cannot use. The handoff acknowledges this: “the timeline's link to the source goes to the clinical history, which a billing-only role cannot read.”

Correct this with an authorized source destination for a billing reader. It may be a narrow billing-source projection/page protected by ViewBilling, showing only the charge provenance that is appropriate for billing (for example the plan item/procedure, completion identity, performed time, and charge linkage), or an equivalent existing authorized destination. Do not widen clinical-history permissions or expose clinical-detail fields merely to repair the link.

Add API and UI tests proving a billing-only role can follow the rendered source link successfully, while that role remains unable to obtain clinical-history detail. Preserve the current direct clinical link or add it only for users who already have clinical-documentation permission. Include the correction in a new immutable R02 handoff attempt with targeted regression and the required full evidence.
