## Required correction

### ALV-N003-R02-01 — P2: A delayed save from an abandoned editing session overwrites a new draft when the same provider is selected again

**Locations:** `src/alveara-client/src/pages/configuration/AvailabilityTab.tsx:139`–167; analogous completion checks at lines 186–206.

Loads capture `loadSeq` and discard superseded generations. Saves only capture `targetId` and compare it with `selectedRef.current`. Provider identity alone cannot distinguish two editing sessions for the same provider. Switching away and back makes an old response appear current again, even though the new editor has already loaded and been edited.

**Deterministic reviewer reproduction:**

1. Load provider A at revision 1 with Monday 09:00–17:00.
2. Change the start to 08:00 and submit. Hold the HTTP response after the server has committed revision 2.
3. Accept discard and select provider B; B loads its own 13:00 start.
4. Return to A. Its fresh read returns revision 2 and 08:00.
5. Create a new unsaved draft by changing A's start to 10:00.
6. Complete the delayed response from step 2 with revision 2 and 08:00.

Expected: the new editor retains 10:00 and remains dirty. Actual: it shows **08:00**, because the old response calls `setRows` and `setSaved` in the new session. The reviewer assertion fails with `Expected 10:00; Received 08:00`. This loses input without a discard confirmation for the new draft. The probe uses realistic committed-write/read ordering; it does not require a stale database read or a backend defect.

The same provider-ID-only pattern is present in blocked-time add/remove success and error completions. Their return-to-provider risk is inferred from code; this review directly reproduces the weekly-save path.

**Required correction:** Bind every asynchronous write completion, including success/error notifications and subsequent blocked-time refreshes, to the editing-session generation as well as the provider identity. Advance that generation on provider changes and relevant reloads, capture it before a write, and discard responses from abandoned sessions even if the same provider is selected again. Keep request identity independent from domain provider identity. Also prevent an in-flight save from replacing edits entered after its submitted snapshot, using an explicit pending-write policy or draft-generation check.

Add permanent deterministic regression coverage for A-save → B → A → new draft → old response, and equivalent stale completion/error handling for blocked-time operations. Assert that the fresh draft remains visible, dirty and saveable and that its loaded revision is retained. Preserve the existing out-of-order load, dirty-switch, conflict/retry, navigation and backend concurrency regressions.

The R02 package's statements that every completion is protected and all R01 findings are closed are therefore too broad. Correct the evidence and extension-pattern guidance in the next attempt.
