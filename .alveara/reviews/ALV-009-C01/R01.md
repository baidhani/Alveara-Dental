## Ruling

R01 Stage 2 **does not qualify**. The full run contains one client-test failure and the frozen backend identity contract used for the run is incomplete. Therefore R01 cannot be closed as `APPROVED`, and this does not authorize the next companion item.

### ALV-009-C01-R01-01 — Frozen backend identity contract is incomplete

The frozen Stage 1 evaluator expected **4,896** backend tests: 4,734 baseline IDs plus 162 new IDs. The Stage 2 run instead passed **4,906 / 4,906**, with all 4,734 baseline IDs unchanged and passing, and **172** new IDs passing. The evidence identifies ten new, passing recall-permission cases omitted from the Stage 1 allowlist. The associated test coverage is present in `src/Alveara.Api.Tests/RecallCalculatorTests.cs` and `src/Alveara.Api.Tests/NotificationPermissionTests.cs`.

This is an evidence-contract failure, not a product-test failure. The R01 4,906 result cannot be retroactively made to satisfy the frozen 4,896/162 contract by editing the evaluator or review result.

### ALV-009-C01-R01-02 — Full Vitest run contains a nondeterministic failure

The full Vitest run failed one pre-existing test:

`src/PatientWorkspace.test.tsx > editing a patient > saves only on request, sends the version it read, and shows the saved values`

The expected city was `Dallas`; the submitted PUT contained `AustinDallas`. Six isolated executions subsequently passed, which supports an intermittent synchronization issue, but does not qualify a frozen full run that itself failed. The test must be made deterministic without changing the product behavior it verifies.

## Required R02 Stage 1 resubmission

1. Correct the test synchronization in `PatientWorkspace.test.tsx` so the clear operation is observed before typing the replacement value. Preserve the behavioral assertion that saving is explicit and uses the loaded version.
2. Rebuild the backend identity manifest from the actual baseline and changed backend test surface. The R02 frozen expectation must cover exactly **4,906** passing IDs: 4,734 baseline plus 172 new, including the ten recall-permission cases.
3. Provide focused R02 evidence for the synchronization fix, including repeat/stress execution sufficient to demonstrate the former race is addressed, plus the revised identity-manifest derivation and comparison.
4. Submit a new **Stage 1 handoff only**. Do **not** start a full regression run before that handoff receives `APPROVED_PENDING_REGRESSION`.

The existing R01 full backend result remains useful evidence that the implementation’s backend tests passed, but it cannot qualify the failed R01 Stage 2 under the two-stage protocol. This is a companion-review correction; it does not reopen the portal STORY-009.
