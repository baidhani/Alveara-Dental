## Blocking finding

### ALV-015-C01-R01-01 — Catalog inactivation does not warn about treatment-plan use

ALV-N005 established `IProcedureUsageSource` specifically so every consumer of a catalog procedure can be counted before inactivation. This attempt creates that consumer: every `TreatmentPlanItem` persists both `ProcedureId` and `ProcedureVersionId`.

However, the production registration in `Program.cs` still registers only `FindingLinkProcedureUsageSource`. No treatment-plan usage source exists, and the test helpers construct `ProcedureCatalogService` with only that odontogram source. Consequently, `GET /api/procedures/{id}/usage` and the `usage_confirmation_required` inactivation protection can report zero uses for a procedure that is present in one or more treatment plans.

The plan procedure and copied fee remain historically safe after inactivation, but the required usage warning is absent at the moment it becomes materially necessary. The handoff’s own next-story-impact document identifies this omission; it cannot remain deferred while approving the story that introduced the new references.

## Required correction for R02

1. Add a read-only `IProcedureUsageSource` implementation over `TreatmentPlanItems`, registered with the existing odontogram source. Count every persisted plan item referencing the procedure, including withdrawn/completed items, because historical references must still be visible before inactivation.
2. Add service/API/integration tests that create a real plan item, assert the usage breakdown includes the treatment-plan source, require explicit `acknowledgeUsage` before inactivation, and show that the existing plan snapshot remains readable while the inactive procedure cannot be added to new work.
3. Update the catalog’s user-facing inactivation warning to expose the treatment-plan count through the existing usage response; add frontend coverage only if the source breakdown is not already rendered generically.
4. Regenerate the R02 handoff with focused correction evidence and rerun the affected catalog/treatment-plan tests, the full serial backend suite, and the catalog/treatment-plan real-backend regression evidence. Keep the runner serial.
