## Required correction

### ALV-008-C02-R01-01 — Historical chart evidence is not deterministic at an equal timestamp

The binding C2 requirement was that reconciliation use durable completion-time chart evidence so a later legitimate odontogram change does not make a valid completion fail Gate D.

`CompletedProcedureService.Reconciliation.ChartMismatchesAsync` instead selects the finding version with the greatest `VersionNumber` among every version whose `OccurredAtUtc <= CompletedProcedure.FinalizedAtUtc`. The completion chart write and any later odontogram operation both take their time from the practice clock. When a later legitimate state/history change has the same timestamp precision as the completion—a normal possibility with a clock of finite resolution or a fixed practice clock—the later version satisfies `<=`, wins by `VersionNumber`, and can produce a false `chartMismatch`.

The supplied later-change test uses a later operation but does not prove the equal-timestamp boundary. The design response expressly required durable or deterministically derived evidence; timestamp-only selection with an inclusive comparison and no completion-linked version boundary does not meet that rule.

Correct this by recording an unambiguous completion-time chart-history boundary for `Updated` and `AlreadyCompleted` outcomes, such as the qualifying finding-version number on the immutable completed-procedure record, then reconcile against that exact version. If an equivalent design is used, it must be immutable, uniquely identify the historical version observed or written by the operation, and work for both authoritative completion and adoption. Do not use a timestamp-only approximation.

Add coverage for all of the following:

1. an adoption that writes a completed finding version and reconciles cleanly;
2. an adoption that observes an already-completed finding and reconciles cleanly;
3. a later legitimate finding change at the **same practice-clock instant**, which still reconciles cleanly; and
4. missing, altered, or non-completed qualifying version evidence, which is reported as `chartMismatch`.

Preserve the existing C1 behavior, transaction guarantees, route retirement, and parent-regression mapping. Submit the correction as immutable R02 evidence with the affected migration/schema, backend, frontend if applicable, and real-browser regression proof.
