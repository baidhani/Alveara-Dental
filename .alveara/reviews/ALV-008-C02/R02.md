## Evidence and findings

1. **R01 correction is implemented at the evidence boundary.** `CompletedProcedure` now persists the exact `ToothFindingVersionNumber` alongside the existing chart finding reference. The two authoritative completion paths save the staged chart change, obtain each referenced finding's active completed version, and write that exact version on the completed-procedure row within the same transaction. Reconciliation uses the persisted `(findingId, versionNumber)` evidence rather than choosing a version from a timestamp range.

2. **The equal-timestamp defect is directly covered.** The R02 regression reproduces a completion/adoption and a subsequent chart withdrawal at the same fixed clock instant, then verifies reconciliation remains clean because it evaluates the recorded version. The R02 negative-control evidence includes the corresponding mutation that replaces the recorded version with a latest-version lookup and reports that control killed.

3. **Database enforcement is present.** The migration adds the version-number column, consistency check, and trigger enforcement. The trigger rejects missing, future, non-completed, inactive, or wrong-finding chart evidence. The R02 test suite includes database-trigger coverage for invalid evidence.

4. **Historic data has durable derived evidence.** The migration backfills the earliest active completed chart version at or before each historic procedure's finalization, a deterministic rule that avoids selecting a later same-instant event. The migration regression exercises the same-timestamp historical scenario and verifies the derived stored version. This is an appropriate migration treatment where the originally observed version was not previously stored.
