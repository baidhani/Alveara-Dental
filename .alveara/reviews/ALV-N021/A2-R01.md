## Required correction

### CR-1 — fixed ISO clock input still depends on host culture

`src/Alveara.Api.ChainHost/ChainHostMain.cs` parses the documented `CHAIN_CLOCK_UTC` ISO-8601 value using:

```csharp
DateTimeOffset.TryParse(..., null, DateTimeStyles.AssumeUniversal, ...)
```

`null` selects the process culture. This is a fixed-format machine input introduced/retained in the chain host and contradicts T-2's explicit-culture contract. The current source guard only detects `ParseExact`/`TryParseExact`, so it does not protect this call.

Correct it by parsing this documented ISO input with `CultureInfo.InvariantCulture` and the appropriate UTC/adjustment styles. Add focused coverage that demonstrates the identical accepted clock value under at least `th-TH` and the nonstandard-time-separator culture already used by `TimeCultureGuardTests`. Expand the guard or add a narrow companion guard so documented fixed ISO parsing cannot regress to a current-culture overload.
