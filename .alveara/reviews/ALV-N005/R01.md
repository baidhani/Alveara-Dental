## Blocking finding

### ALV-N005-R01-01 — CDT provenance is not enforced for every non-local code

The implemented behavior contradicts the handoff’s own delivered-scope statement that `SourceName` is “required for any non-local system,” and it falls short of the plan’s explicit code-system/source and provenance requirement.

`ProcedureRules.Validate` requires a source only when `CodeSystem == External`:

```csharp
if (system == ProcedureCodeSystems.External && sourceName is null)
```

A caller can therefore create a `CDT` procedure with code `D1234` and no `SourceName` or `SourceVersion`. The database schema has no corresponding `ProcedureVersions` constraint, so a direct database write can persist the same invalid provenance state. Existing tests prove a CDT record *with* source metadata, but do not prove that missing CDT provenance is rejected.

This is material because the story’s CDT-ready design relies on preserving the source/version/provenance of externally sourced codes without changing their stable internal identity. A catalog entry labelled CDT but not tied to the licensed source held by the practice cannot meet that contract.

## Required correction for R02

1. Treat `CDT` and `External` as non-local code systems for provenance validation. Require a nonblank `SourceName` for both; preserve the rule that `Local` accepts neither source name nor version. Decide and document whether `SourceVersion` remains optional, as the plan permits optional source/version metadata.
2. Enforce this at the database layer as well as the service/API layer, using a migration/model constraint that prevents invalid direct inserts or migrations from storing a non-local procedure version without a source, or a local version with source fields.
3. Add focused service, API, and schema-bypass tests for CDT-without-source and External-without-source. Retain the existing positive CDT/external provenance tests.
4. Regenerate the handoff evidence from the corrected implementation, rerun the affected tests plus the full backend serial suite and catalog UI/real-backend evidence, and keep the runner serial.

Do not mark ALV-N005 complete or start STORY-015. The package’s remaining evidence can be retained where the correction does not affect it.
