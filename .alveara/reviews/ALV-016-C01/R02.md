## Evidence and findings

This establishes that R02 fixed a real behavior rather than accepting a fortunate rerun.

It does not retry timeouts, connection loss, cancellation, or domain refusals. Each subsequent attempt begins after the deadlocked transaction has rolled back, clears the change tracker, re-reads the plan, and rechecks the caller version and idempotency key.

3. **The domain-safe outcomes are directly proved.** Ten `CompletionDeadlockTests` engineer deterministic real SQL Server deadlocks. They prove retry-to-success exactly once, retry exhaustion to documented `save_failed` (503) with no stored clinical, audit, or ledger effect, an overlapping winner with exactly one resulting set and no duplicate charges, idempotent replay of an identical retry, and the equivalent adoption behavior. The tests also prove the classifier rejects non-1205 errors and that only a bounded number of retries occurs. The relevant negative controls account for 13 mutants: 12 killed and one documented equivalent mutant.

It turns a previously unhandled deadlock-victim infrastructure exception into the already documented safe retry or `save_failed` outcome.
