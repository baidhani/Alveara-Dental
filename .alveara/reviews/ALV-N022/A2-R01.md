## What is correct

The implementation correctly follows the approved path split in ordinary operation:

- a new diagnosis against a Finalized encounter is refused with `409 encounter_finalized`, has no normal-path diagnosis/version/audit write, and the diagnosis picker excludes finalized encounters with the reviewed message;
- completion, adoption, and append-only amendment retain same-patient Draft **or** Finalized attribution without changing the encounter;
- documents/referrals and signed Draft behavior are unchanged; and
- the focused Stage 1 evidence is strong for those ordinary paths: backend **125/125**, client **15/15**, a fresh-database real-browser workflow **1/1**, and both approved negative controls caught/restored.

No broad/full regression, chain, or unrelated walkthrough is required for this review.

## CR-1 — finalization race permits prohibited new diagnosis

`DiagnosisService.RecordAsync` reads the encounter status with `AsNoTracking`, then separately inserts the diagnosis.  There is no transaction/lock or database constraint tying that check to the insert.  If another request finalizes the encounter after the status read but before `SaveChangesAsync`, the insert can succeed against an encounter that is now Finalized.

The handoff discloses this exact window.  It conflicts with the approved A2 rule that diagnosis creation against a Finalized encounter is refused **before any write**, and it is a clinical-record integrity boundary.  An ordinary-path unit test and the browser workflow cannot establish this invariant.

## Required R02 correction

Implement a database-enforced diagnosis-insert guard, through a reviewed migration/trigger or equivalent authoritative database mechanism, that rejects a new diagnosis when its linked encounter is Finalized.  It must:

1. preserve the existing same-patient and immutable-link protections;
2. apply only to a new diagnosis insert, not to legitimate correction/withdrawal of an already-recorded diagnosis;
3. map the guard’s expected refusal through the API/service to the reviewed `409 encounter_finalized` response without exposing SQL text or PHI; and
4. preserve same-key idempotent replay for a diagnosis recorded before the encounter finalized.

Add a deterministic concurrent/interleaving test that finalizes the encounter after the service has passed its initial application check but before diagnosis persistence.  It must prove no diagnosis, diagnosis version, or audit row is committed and that the caller receives `encounter_finalized`.  Also add direct persistence coverage proving the database guard rejects a raw/direct insert that attempts the same forbidden state.

Because this introduces a migration/database invariant, R02 must include focused migration up/down or upgrade coverage, plus the relevant focused diagnosis tests and the existing browser workflow.  Keep each command within the five-minute policy; ask before any command that would exceed it.

Do not alter the approved completion/adoption/amendment rule, start Stage 2, run broad/full regression, or begin A3.  Preserve R01 unchanged and return a new immutable A2-R02 Stage 1 package.
