## Findings and required corrections

### ALV-002-C01-R01-01 — P1: Required permission-aware audit viewer is missing

**Locations:** `.alveara/handoffs/ALV-002-C01/R01.md:24`–26; `src/alveara-client/src`; `src/Alveara.Api/Controllers/AuthController.cs` (`GetAuditLog`).

The handoff claims `GET /api/auth/audit-log` satisfies the UI viewer. Inspection finds no frontend audit page, route, service or viewer consuming that endpoint. A user cannot review existing history through the product. The eight packaged browser tests exercise existing authentication/security-administration workflows, not an audit viewer.

**Correction:** Implement a basic viewer in the shared application shell using real audit data and `ViewAuditLog` capability checks. Preserve server-side enforcement and show loading, empty, error and denied states. Display useful actor/action/target/time context for existing events; expose the shared event metadata where appropriate. Include permission-aware navigation/direct-route coverage and a visible real-backend demonstration. A clinical/financial domain screen or audit-edit capability is not required.

### ALV-002-C01-R01-02 — P2: Required stale-edit/conflict presentation pattern is missing

**Locations:** `.alveara/handoffs/ALV-002-C01/R01.md:27`; `src/Alveara.Api/Architecture/Concurrency/ConcurrencyConflictException.cs:19`; `src/alveara-client/src`.

`ToProblem()` returns a useful stable backend shape, but no UI component or interaction presents it to a user. The handoff expressly acknowledges that no controller or UI consumes the shape. This completes the shared conflict-result primitive, not the separately required UI presentation pattern.

**Correction:** Add a reusable, accessible UI conflict presentation with a clear explanation and a safe recovery/reload path that does not silently overwrite another user's changes or discard unsaved work. Demonstrate it in focused UI tests or an appropriate existing edit flow. Do not invent clinical/financial lifecycle semantics or reintroduce the rejected UserAccount rowversion design merely to obtain a screen. Keep the StaffProfile concurrency demonstration unless evidence requires changing it.

### ALV-002-C01-R01-03 — P2: Audit-failure test does not exercise required audit persistence or rollback

**Locations:** `src/Alveara.Api.Tests/AuditLogImmutabilityTests.cs:103`–121; `src/Alveara.Api/Architecture/Auditing/AuditService.cs:13`–17; handoff failure-path and acceptance claims.

The test changes a business field and tampers with an **existing** audit entry, then expects `AuditLogImmutableException`. The SaveChanges guard throws before `base.SaveChangesAsync` runs. No new required audit event is staged through `AuditService.Record`, no audit INSERT fails, and no database transaction is rolled back. The test proves preflight rejection prevents a save; it would still pass if audit/business persistence were not transactionally coupled.

The inspected staging design and existing AccountService transactions support atomic persistence, but the mandated persistence-failure evidence is missing. This is a test/evidence gap, not an independently reproduced loss of audit data.

**Correction:** Retain the existing test as immutability/preflight coverage and add a real audit-insert failure test. Stage a valid consequential business change and a new required audit event through the shared path; cause that audit INSERT to fail using a controlled SQL constraint failure or narrowly scoped fault injection. Verify with a fresh context that neither the business effect nor its audit event persisted. Exercise the actual transaction/coupling boundary and document how callers must use it, including explicit transactions for writes performed outside SaveChanges. Demonstrate recovery after the failure where relevant.
