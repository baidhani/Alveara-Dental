## The review finding ALV-008-C02-R01-01: historical chart evidence must be deterministic
The review required: record an unambiguous completion-time chart-history boundary for `Updated` and `AlreadyCompleted` outcomes (such as the qualifying finding-version number on the immutable completed-procedure record), reconcile against that exact version, for both authoritative completion and adoption, never a timestamp-only approximation; preserve C1, the transaction guarantees, route retirement and the parent-regression mapping; and cover four cases.

**Reproduced first:** `CompletionReconciliationTests.A_later_legitimate_chart_change_at_the_same_practice_clock_instant_leaves_an_adopted_completion_clear` failed on the R01 code (`chartMismatch` 1 instead of 0, with the tie asserted).

**The four required cases (class `CompletionChartEvidenceTests`, real SQL Server, unless noted):**
1. *An adoption that writes a completed finding version and reconciles cleanly:* `An_adoption_that_writes_a_completed_version_records_exactly_that_version_and_reconciles_clean` (the stored version equals the `StateChanged` version the adoption wrote; reconciliation `clean`).
2. *An adoption that observes an already-completed finding and reconciles cleanly:* `An_adoption_that_observes_an_already_completed_finding_records_the_observed_version_and_a_later_change_at_the_same_instant_leaves_it_clear` (the stored version is the version that was already there; nothing was written to the chart).
3. *A later legitimate finding change at the same practice-clock instant still reconciles cleanly:* the reproducing test above (for `Updated`), the second half of case 2 (for `AlreadyCompleted`, after a same-instant withdrawal), and `Rolling_back_and_forward_restores_the_evidence_as_the_first_active_completed_version_which_a_same_instant_withdrawal_cannot_displace` (a same-instant link and a same-instant withdrawal after the completion).
4. *Missing, altered or non-completed qualifying evidence is reported as `chartMismatch`:* `Missing_altered_or_non_completed_chart_evidence_is_reported_as_a_chart_mismatch` (missing version, a version that shows the finding only Planned, a version that does not exist, a version newer than the completion, a version of a withdrawn finding, and a version whose stored history was altered afterwards), each seeded around the new trigger and each reported (`chartMismatch` 1, not `clean`).

**Also proved:**
- The authoritative completion records the version too, including two procedures on one finding in one set (`The_authoritative_completion_records_the_version_it_wrote_and_two_procedures_on_one_finding_share_it`); a completion that moves no finding records none (`A_completion_that_moves_no_finding_records_no_version_and_reconciles_clean`).
- The database refuses bad evidence on its own (error 51173: missing, Planned-only, non-existent, withdrawn, newer than the completion) and the check constraints (a version without a finding, a version of zero); valid evidence is accepted.
- The read refuses a finding that is not an active Completed state or does not exist (`finding_changed`, `finding_not_found`).
- The backfill: rolled back and forward on a history of four versions (Planned, Completed, Linked, Withdrawn, the last three at one instant) the stored version is still the first active Completed one; a completion whose finding never reached Completed, or reached it only after the completion, stays empty and is reported.
- **Preserved:** C1 (`CompletionAdoptionRulesTests`, the service tests), the transaction and rollback guarantees (`CompletedProcedureAdoptionHardeningTests`, `CompletedProcedureServiceTests.A_failed_audit_write_in_either_save_...`), route retirement (`CompletionApiTests`, `RetiredCompletionCallerSearchTests`), the parent-regression mapping (`PARENT_REGRESSION.md`); all in the full serial run.
