## Scope delivered
- **Ten reports** with date, provider and location filters where they are honest (otherwise refused with `filter_not_supported`, and the hub does not send them): schedule, patient flow, recall and follow-up, cancellations and no-shows (`ViewOperationalReports`); production and charges, collections and payments, balances (`ViewFinancialReports`); treatment-plan status, completed procedures, provider activity (`ViewClinicalReports`). Dates are the practice's days in its own time zone converted to a half-open UTC range. A report is read in one snapshot when the database allows it, and says how it was read.
- **Proof of totals.** Financial reports classify every ledger entry into exactly one line and show the lines beside an independent sum of the same entries; the other reports carry a `reconciled` flag; every drill-down total equals the cell it came from (the same predicate builds both). Any number that is not zero opens the records behind it (ids, times, statuses; never a name or a note), paged by keyset.
- **Measurement.** Seven measured metrics (scheduling conflicts, billing corrections, duplicate patient merges, clinical notes not finalized, follow-ups not done on time, cancellations, no-shows), each as counted out of what with a definition version; "Not available" instead of zero when nothing was counted; three things the application cannot observe (duplicate-entry time, administrative time, the overhead reduction) are listed with the reason and never given a number, the 20 to 30 percent reduction being a target only. Baselines are immutable snapshots of a period that is already over, stored with each metric's definition version (database triggers refuse an edit or delete). A comparison shows a change only when the baseline ended before this period started, the definition version is the same and both denominators hold at least 30 records; otherwise the metric shows its value, the reason and no change. A change is worded Higher, Lower or The same, never as an improvement, and carries the sentence that a difference does not show a cause.
- **Export and print.** Every report downloads as CSV from the same report object the screen shows, with the same filter, so the totals are the screen's; it needs the report's own permission, is recorded in the audit log (a run and an export are two entries; if the entry cannot be saved no file is handed over), is refused over 50,000 lines rather than cut, neutralises formula-like text and keeps numbers as numbers. Print opens the browser's dialog with a layout that leaves off the menu, filters and buttons.
- **Hub.** `/reports/:reportId?` lists the reports each role may see by group, with the filter bar in the address, summary cards, drill-down panels, the measurement panel (metrics, baselines, the set-a-baseline form for `ManageMeasurementBaselines`, comparison), download and print; light and dark, axe-clean.
- **Permissions and audit.** Five new permissions (all grantable): `ViewOperationalReports` (Admin, OfficeManager, FrontDesk), `ViewFinancialReports` (Admin, OfficeManager, Billing), `ViewClinicalReports` (Admin, OfficeManager, Dentist), `ViewMeasurementReports` and `ManageMeasurementBaselines` (Admin, OfficeManager). Audit events `ReportViewed`, `ReportExported`, `ReportBaselineSet` carry the report, the length of the range and counts, never a value; a report whose audit entry cannot be saved is not delivered (503 `audit_unavailable`).
- **Performance.** A full year (4,380 appointments, 5,000 ledger entries) answers each report with a small fixed number of database commands; the slowest report took 0.116 s against a 10 s budget (judged only when `ALVERA_PERF_EVIDENCE` names a folder).

## Decisions and deviations
1. **Two permissions for measurement** (`ViewMeasurementReports`, `ManageMeasurementBaselines`), separate from the three report groups, Administrator and Office manager by default and grantable (owner-accepted during slice 5).
2. **A baseline is an immutable snapshot of a completed period**, not a live view, so a later correction to the data never moves it; a period that is not over is refused.
3. **The 30-record minimum is configurable** (`Reporting:MinimumComparisonSample`) and applies to both denominators.
4. **Financial entries are dated by when they were recorded.** The provider filter applies only to production, completed procedures, provider activity, schedule, patient flow and cancellations; collections, balances, follow-ups, treatment plans and measurement refuse a provider or location filter instead of ignoring it.
5. **The CSV is made from the report object the screen shows**, by one writer that turns the report into a summary and one table per list, rather than a second query per report, so the file cannot drift from the screen. An export leaves two audit entries (the run, then the export).
6. **Item 0.** The walkthrough runner now sets `E2E_STORAGE_ROOT` (one line in a shared script), as the owner asked at the previous story's closure (`9f97741`).
7. **The walkthrough seeds its 100 starting ledger line in SQL**, because an account only opens with a charge or an imported opening balance; the payment goes through the real API.
8. **The billing-ledger walkthrough is not fixed in this story** (owner decision): it fails on the last pushed commit already and is excluded from the frozen Stage 2 list.
9. **The reports use the app's print convention** (hide everything but the printable region) because other pages' global print rules hide the rest of the page.
