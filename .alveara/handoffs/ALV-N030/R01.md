## Scope delivered
| Area | Delivered |
|---|---|
| **Deployment Administrator, first-run setup** | `UserAccounts.AccountKind`: one Deployment Administrator at most, enforced by the database. A one-time setup token, issued by the installer command `setup issue-token`: only its SHA-256 hash is stored, it lasts 15 minutes, it is single use, and 5 failures void it. `/setup` gives one identical refusal for every token failure, is rate-limited, and is exactly-once under a race. The account is Admin-role, has no profile, and appears in no staff list or picker; actions are attributed to "Deployment Administrator". |
| **Sign-up and bootstrap removed** | `register`, `bootstrap-admin` and the static secret are gone from the product. Their leftovers are deleted. |
| **Add staff member** | Profile and login in one transaction, with an Idempotency-Key (a replay returns no password). The 16-character temporary password is shown once. It needs ManageUsers and ManagePracticeConfiguration and follows the ALV-N018 role-subset rule. The profile-only create, the link picker and link edits are removed. The legacy-login action is for active records created before logins were required. |
| **Forced password change** | A server gate gives 403 `password_change_required` everywhere except 5 actions. `POST /api/auth/password/change` rotates the stamp and re-issues the session. A completed reset clears the flag. The client page `/change-password`. |
| **Practice Owner** | One active designation (database index and trigger 51311). The first designation only (a second gets 409). The target must be active staff with an enabled staff login. Two methods: by the Deployment Administrator through Add staff member, or by an administrator through the upgrade transition notice. Labels in Security Administration. |
| **Upgrade data step** | With exactly one profile-less Admin, that account becomes the Deployment Administrator (audited). With 0 or 2+, nothing is converted. An owner is never set. |
| **Setup mode and restart (section 16)** | The mode is decided before Build: NotInstalled, UpgradeRequired, Setup or Normal. The API never migrates. Outside Normal, the app's background services are not registered and `/api` answers 503 except what the mode allows. The status route gives exactly four bodies. Exit 75 after a successful setup. The dev restart loop; the client's server-state screens and the restart wait. |
| **Test support (R07)** | `Alveara.Api.TestSupport` with `POST /api/test-support/accounts` and (owner-approved) `/staff-profiles`, only on ChainHost under Test, opted in, on loopback. The runners run on ChainHost in both clock modes, with `-DatabaseState` and the restart-on-75 watch. |

## Disclosures
(The full list is in `PENDING_DISCLOSURES.md`; the essentials follow.)

### Deviations from the briefs
1. **Identity call.** The identity fields and the forced-change exemption are on `GET /api/auth/permissions` (the client's identity call), not on the Administrator-only `whoami`.
2. **Section 8 replaced by section 17 (R07).** There is no product start-up split and no TestHost executable.
3. **Second fixture route (owner-approved R07 implementation extension).** `POST /api/test-support/staff-profiles`, under the same guards. An unlinked profile needs `legacyUnlinked: true`.
4. **G3** reads MSBuild's publish file list instead of a full publish, which would run `npm ci` and `npm run build`.
5. **`DeploymentGuardMiddleware` exempts `/api/setup`.** In Setup mode the invariant monitor, a background service, is not registered, so the guard refused the setup routes. The setup routes read and write nothing that depends on the deployment settings.
6. **Status within one process.** The status route answers from the process's mode. After a successful setup it still says "setup" until the restart.
7. **S18 "one migration behind"** is made by removing the newest `__EFMigrationsHistory` row, which is exactly what the probe reads.
8. **S21 gap.** The browser check that an unreachable server gives up within its bound is not covered. The bounds are in code (15 s, 3 retries, 1/2/4 s backoff).

### Assumptions
- **Password length:** a minimum of 12 characters for setup and for the self-service change.
- **Gate scope:** the gate covers only endpoints that require a signed-in user.
- **Pickers:** message recipients count as a person picker, so the Deployment Administrator is excluded from them.
- **Permission checks:** ManageUsers is checked inside the staff-member actions, because `RequirePermission` cannot be stacked.

### Owner decisions
- **U-038.** `CollectPayments` is added to the default Office Manager set.
  - **New rule:** default Front Desk permissions ⊆ default Office Manager permissions, guarded by `RoleSubsetInvariantTests`.
  - **Interpretation:** "a custom Front Desk account" means a practice customising the Front Desk ROLE.
  - **Out of scope:** per-account grants.
  - The impossible Dentist test now targets a Hygienist, and the Dentist-only permission can never be held by an Office Manager.
- **U-040 and U-042 (pre-existing, from ALV-N025 slice 1 and ALV-N026 S3).** These were **test-selector corrections only**: the auth walkthrough's text checks matched new elements (the audit event filter options, and "The backup completed." status line). There was no product change.
- **U-041 (pre-existing, unassigned).** The billing walkthrough's "no form before billing" assertion fails identically before ALV-N030. Prescriptions replaced billing in the sample (owner).
- **Dashboard wording.** The Deployment Administrator's notice uses the owner-approved text of 2026-11-24 (commit `44545eb`, not run).

### Test data, not product
- **Setup-completed mark.** Every backend test database gets a setup-completed `BootstrapStates` row, so tests run in Normal mode; setup tests clear it.
- **Walkthrough databases.** The walkthrough runner marks its database as set up by default (`-DatabaseState SetUp`). The chain runner marks it too.

### Defects found by own verification (all fixed before the passing results)
- the removed routes answer 405 rather than 404 when a client build exists;
- a second Deployment Administrator was seeded in a test;
- the fixture reply was missing presentation fields;
- template-literal staff creates were missed by the 5c rewrite;
- unlinked providers were sent through the fixture route;
- a weak S14-a check;
- the guard blocked `/api/setup` in Setup mode;
- ChainHost crashed at shutdown and lost exit code 75;
- the client sent `/login` back to `/setup` after the restart.

### Run over estimate
The first slice 7 focused group ran **8 m 8 s** against a 3-4 minute estimate. It ran in the background and could not be stopped at a safe point. The 5b run of about 16 minutes was owner-approved in advance.
