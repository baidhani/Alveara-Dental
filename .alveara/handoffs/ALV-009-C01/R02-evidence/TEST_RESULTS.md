## Finding ALV-009-C01-R01-02: the nondeterministic `PatientWorkspace.test.tsx` failure
- **Root cause (reproduced, `artifacts/race-probe/race_probe.test.tsx`):** `PatientDetailsPanel` re-seeds its form values from the loaded patient in an effect that runs after the field first appears. A React passive effect can still be pending when the field is found; the test's `userEvent.clear` then queues `""`, the pending effect queues the patient's values after it, and the typed text lands on `"Austin"`: the observed `AustinDallas`. The probe edits in exactly that window and fails 3 of 3 runs with `expected 'Austin' to be ''`; the same edit made after `await act(async () => {})` is kept (passes 3 of 3). A person cannot edit within milliseconds of the form appearing, so the product behavior is correct; the test needed to wait.
- **Fix (test only):** the test flushes pending effects with `act` before the first edit, then waits for the field to read `""` after the clear and `"Dallas"` after the typing, before checking "Unsaved changes" and saving. Its assertions that saving is explicit, sends the version it read (`rowVersion: "v1"`) and shows the saved values are unchanged; the product file is not touched.
- **Repeat and stress evidence:** 40 of 40 isolated runs of the file (19 of 19 tests each) while 48 CPU-burning processes ran on the 24-core machine (`artifacts/race-probe/stress_fixed_isolated.txt`). Disclosure: the R01 version of the test also passed 12 of 12 in the same kind of load test, so repeat runs by themselves cannot show the race is gone; the deterministic probe pair above is the evidence of cause and fix, and the repeat runs show no regression.
- **Full Vitest on the R02 tree:** **102 files, 1,617 tests passed** (`artifacts/gates/vitest.txt`).
