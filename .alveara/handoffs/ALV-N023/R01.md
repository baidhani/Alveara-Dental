## Disclosures
- **Implementation vs swept tree:** the sweep ran on `f9c0d2a`; `2ade215` differs by `TreatmentPlanN023Proof.test.tsx`, PROGRESS.md and the handoff note (`git diff --stat f9c0d2a 2ade215`: 3 files). Mapping the evidence found three section 6 rows (F-102, DR-8, D-03) whose client proof was missing although the code existed; with the owner's approval the 4 tests were added, each shown to fail on a planted break.
- **Job test class name:** the brief named `RecallJobTests`; the section 4.4 tests are in `UnscheduledTreatmentJobTests`.
- **Setting a target date starts a new follow-up episode** (it appends a state row, so the open task closes "Continued in a new follow-up" and a new one opens) - per the approved key algorithm.
- **Rename reason** is enforced in the service only; the database CHECK was not widened (old Renamed rows have no reason).
- **Audit** has no answer-source category field; it says the person who gave the answer is recorded on the plan (addendum 01 A1-3 limit).
- **Two extra read endpoints** in slice 4 (`practice-header`, `linkable-appointments`): within brief S13/C1; needed because dentists cannot read `/api/config/practice`.
- **Own test mistakes on first runs (fixed in the tests, not the code):** reason_required code, missing idempotency key, plan create 200 not 201, comparison fixture shape, calls-helper prefix, a "done" regex; the browser spec first expected "Completed" for a plan with one completed and one declined procedure, which the approved matrix makes Closed (CompletedOrDeclined) and locked.
- **Handoff-note error corrected:** the note said `nothing_unanswered` is a 400; the server answers 409 and the client test stub follows the server.
- **Slice 2 hit the stop rule** (three state/action ambiguities) -> addendum 01, approved before implementation resumed.
- **Tooling:** on this machine Vitest started from Bash or via `cmd` intermittently failed to load its runner ("failed to find the runner", no test executed) on an unchanged tree; runs started directly from PowerShell were reliable. Every recorded vitest result is from a run that executed its tests.
- **Leftover test data:** one `AlveraTest_*` database and one Temp template backup existed before this story; counts identical before and after; not removed.
- **Dev database** `AlveraDev` does not have the new migration (not migrated without the owner's permission).
