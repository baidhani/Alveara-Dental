## R01 review decision being corrected

`CHANGES_REQUIRED`, three blocking findings:

1. **N001-R01-01 (P1)** — `useConnectionStatus` treated any HTTP 200 as "connected" via `res.ok` alone. Without a dev proxy, a relative `/api/health` request against the Vite dev server (no listener behind it) returned Vite's own HTML fallback — a genuine 200 — which the hook accepted as a healthy API. The reviewer independently reproduced this with `Invoke-WebRequest` against a running Vite server with no API listening.
2. **N001-R01-02 (P2)** — the "usable at agreed desktop and tablet widths" and "visible demonstration" acceptance items were only supported by jsdom/Testing-Library structural checks (DOM landmarks, a CSS-string match), not genuine rendered-layout or real browser interaction evidence.
3. **N001-R01-03 (P2)** — the dark-theme primary button gave white-text contrast of ~2.808:1 (normal) and ~2.154:1 (hover), both under the WCAG AA 4.5:1 threshold for normal text.

Plus five non-blocking notes: TEST_RESULTS.md's total-check arithmetic was wrong; BUILD_STATE.md still said `src/`/`tests/` were empty under "What actually exists" (contradicting its own opening paragraph); the handoff referenced a repository evidence path where it meant a packaged ZIP path; `NotFoundPage` nested a `<button>` inside a `<Link>`; `FormField`'s `aria-describedby` could reference a hint id that wasn't actually rendered when an error was also present; and the empty-module-registry failure path (explicitly required by the story prompt) was neither demonstrated nor tested.

## Corrections made

1. **Connectivity false positive (N001-R01-01):**
   - Added a Vite dev-server proxy (`vite.config.ts`): `/api` → `http://localhost:5072`, matching `src/Alveara.Api/Properties/launchSettings.json`'s `http` profile exactly (previously undocumented/ambiguous against three different ports mentioned across files — now single-sourced).
   - Rewrote `useConnectionStatus.ts`: validates the response's `content-type` is `application/json` and that the parsed body matches `{ status: "ok" }`, not just `res.ok`. Added a 4-second per-request timeout via `AbortController`. Added an in-flight guard so overlapping polls can no longer leave a stale "connected" status hanging indefinitely.
   - Added `useConnectionStatus.test.ts` (6 tests): API up, API down (rejected fetch), the exact HTML-fallback-as-200 scenario the reviewer reproduced, an unexpected-but-200 JSON payload, request timeout, and recovery (disconnected → connected across a simulated poll interval).
   - **Independently reproduced and confirmed fixed against the real dev server + API**: with only Vite running and no API listener, `curl http://localhost:5173/api/health` now returns a genuine `502 Bad Gateway` (the proxy correctly fails), not a fake `200`. With the real API running on port 5072, the same request returns the real `200 {"status":"ok"}` through the proxy.

2. **Real-browser evidence (N001-R01-02):** Added Playwright with a real, headless Chromium browser (not jsdom):
   - `playwright.config.ts` declares the two required viewports explicitly: desktop `1280×800`, tablet `768×1024`.
   - `e2e/shell.spec.ts` (20 tests across both viewports): dashboard load + no horizontal overflow, navigation to showcase + every control renders + long-text wrapping check, the full keyboard-only path (skip-link → tab → Enter), unknown-route handling with a single interactive return control, form validation appear/clear, notification toasts, disconnected banner appearing/clearing against a mocked `/api/health` route, connected state showing no banner, theme toggle switching and persisting across reload, and an explicit desktop-vs-tablet sidebar-layout structural assertion (narrow column vs. collapsed top bar).
   - `e2e/accessibility.spec.ts` (12 tests): axe (WCAG 2 A/AA tags) run against Dashboard, Showcase, and the not-found page, each in both light and dark theme — not the dashboard alone.
   - All 32 real-browser tests pass, at both viewports.

3. **Dark-theme contrast (N001-R01-03):** Changed `tokens.css`'s dark-theme `--color-primary`/`--color-primary-hover` from `#5fa2c7`/`#7fb8d8` (≈2.8:1/≈2.2:1 against white) to `#1f4459`/`#27587a` (≈10.3:1/≈7.6:1). Added `contrast.test.ts`, which parses `tokens.css` and computes actual WCAG relative-luminance contrast ratios for both themes' primary/primary-hover backgrounds against their contrast colour, failing if either ever drops below 4.5:1 again. Independently reconfirmed by the new axe suite passing color-contrast checks in dark mode.

4. **Smaller fixes:**
   - `NotFoundPage` now uses a new `ButtonLink` component (a single `<a>` styled like `Button`, not a `<button>` nested inside a `<Link>`).
   - `FormField`'s `hintId` is now only set when the hint `<p>` actually renders (i.e., `hint && !error`), so `aria-describedby` never references a non-existent node. Added a test for the simultaneous hint+error case asserting `aria-describedby` resolves to exactly the rendered error id.
   - Added `AppShell.emptyRegistry.test.tsx`, mocking `moduleRegistry` to `[]` and confirming the shell renders without crashing and the main content region stays reachable.

5. **Documentation corrections:**
   - `TEST_RESULTS.md` (this attempt's version, in `R02-evidence/`) states the correct per-suite counts instead of an incorrect combined total.
   - `BUILD_STATE.md`'s "Course scaffold" bullet no longer claims `src/`/`tests/` are empty; it now points to the "Application shell" section for current truth.
   - This handoff explicitly distinguishes repository evidence paths (`.alveara/handoffs/ALV-N001/R02-evidence/`) from packaged ZIP paths (`evidence/`, `review/`) wherever both are mentioned.
