## Scope delivered (implementation scope of the prompt, item by item)
- **Structured medical and dental history with longitudinal change history and reviewed/verified-by/on attribution** — `ClinicalRecordItem` (+ append-only `ClinicalRecordItemVersion`), `ClinicalSectionReview` (who reviewed, when), `ClinicalRecordEvent` timeline; every change names the staff member and time.
- **Allergies with active/inactive/resolved status, reaction/severity, history-preserving correction** — statuses `Active/Inactive/Resolved`; correction adds a version, never rewrites; an item entered in error is marked removed with a required reason.
- **Medications with active/inactive/discontinued state and history** — `Active/Inactive/Discontinued` (database check per kind) with the same version history.
- **Explicit unknown / not reviewed / none known** — three different statements (no row = not reviewed; `NoneKnown`; `Unknown`), none an item; plus derived `Reviewed` / `NeedsReview`.
- **Vitals with encounter/date attribution** — `EncounterVitals` (encounter, patient, measured-at, recorded-by); void with reason, never edit.
- **SOAP/progress notes, treatment notes, free text, encounter linkage** — `EncounterNote` (Subjective, Objective, Assessment, Plan, Progress, Treatment) per encounter, up to 8000 characters.
- **Configurable note templates owned by the clinical-documentation domain** — `NoteTemplate`/`NoteTemplateSection`, own endpoints and own permission `ManageClinicalTemplates`; nothing added to practice configuration.
- **Draft/signed/finalized states, addendum/amendment preserving original, completeness indicators** — Draft → (Signed, locked) → Finalized; addenda now name what they amend; `readyToSign`/`missingNotes`/`missingSections` and the review list.
- **UI** — history summary (clinical record) and encounter note editor; template picker; structured sections; sticky save indicator; signing/finalization review listing unresolved items; timeline of amendments.
- **Security/audit/integrity** — clinical role permissions (server-side); finalized content immutable (service + triggers); every save, sign, unsign, finalize and amend audited with user and time and no clinical text.
- **Failure paths** — autosave/save failure (text kept, "Save note", no retry loop), stale edit (409 banner, in-place reload), signing with unresolved required data (409 naming each), amendment failure (nothing stored, key not consumed).

## Decisions and deviations from the prompt's wording
1. **Record and encounter are separate stores.** STORY-005's per-encounter entries stay exactly as they were (its contract is immutable); the longitudinal record is the running chart. A record change can name the encounter it was made during through the API (`encounterId`) but the encounter screen does not yet drive it.
2. **Signed is a lock, not a database state.** `Signed` sits between Draft and Finalized without widening STORY-005's `CK_Encounters_Status`; the lock is enforced by the service (`encounter_signed`), finalized immutability remains database-enforced.
3. **Required notes count only when written.** A required note that is blank or still exactly the template's starter text is unwritten; STORY-005's finalize rule is unchanged when no template is applied.
4. **Adding an item withdraws a stale "none known"/"unknown"** in the same save (recorded in the timeline) instead of refusing, because adding the item is the clinician correcting the statement.
5. **Reviewed is derived.** A section is `Reviewed` only while no item changed after the confirmation; this cannot drift from the data.
6. **One template per encounter**, applied once; later template edits never change an encounter that used it.
7. **Vitals are metric, plausible-range checked, never rounded silently**; a typo guard, not decision support.
8. **Names, not ids, for attribution** (staff profile display name; "Staff member" when an account has none).

## Defects found and fixed by this attempt's own verification
- **A race in my own code**: two clinicians adding at once to a section marked none known both deleted the same statement; the loser surfaced as an unhandled concurrency error (a 500). Found in a review pass, fixed (retry once; benign-race handling for withdrawals), and a test that fails without the fix was added (mutation-verified).
- **A duplicate autosave** (the real test caught it): a timer scheduled while typing still fired after the blur save and sent the same text twice; the timer now re-checks before sending.
- **Test-side races** (three): a text match that also matched an open textarea or another note's "Saved." text; fixed by waiting on the save indicator.
