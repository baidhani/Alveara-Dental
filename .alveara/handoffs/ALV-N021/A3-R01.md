## What changed
1. **Practice zone in the session (server).** `practiceTimeZoneId`, the canonical IANA id, on every successful authenticated `GET /api/auth/permissions` for every role. A Windows-id configuration is converted; a zone without an IANA form stops start-up. `PracticeZoneIds.TryWindowsId` is the server-owned mapping for a future Windows client; only the IANA id is published.
2. **Typed practice-local times (server).** One parser, `PracticeLocalInput`: exact invariant ASCII `yyyy-MM-ddTHH:mm` (`:ss` on the two performed-time routes), `Unspecified` kind, converted only by `IPracticeClock.FromPracticeLocal`. `performedAtLocal` on complete-procedures and adopt-completion, `dueAtLocal` on follow-up create and update, `measuredAtLocal` on vitals. Codes `invalid_local_time`, `local_time_does_not_exist`, `local_time_ambiguous`, `ambiguous_time` (both fields named), each 400 with the field. Legacy `...Utc` alone still accepted (D-2). Services unchanged.
3. **Client helpers and session state.** `time/practiceTime.ts` is the only code that turns an instant into practice time or derives a practice day; every helper returns null without a usable zone. The auth state keeps the zone from every authenticated response, flags a genuinely observed change once, and forgets it at session end.
4. **Every screen.** 63 instant displays in 50 files render in the session zone ("Time unavailable" without one); `formatMoment` lost its browser fallback; the Flow Board clock is in the practice zone; the sign-in lockout reads "Try again in N minutes" (no session zone exists there); a shell banner when no zone is usable and a dismissable notice when a newer response changes it.
5. **"Today" and inputs.** Every "today" default, preset and limit uses the practice day; prefills use the practice zone; the four forms send plain local text and never convert it in the browser.
6. **Guard.** `tests/practice-time-guard.test.mjs`: browser-zone instant formatting and browser-local calendar days are refused outside the helper module, with a six-entry reviewed allowlist.
7. **Two-zone real-browser proof.** Chicago and Tokyo browsers against one Chicago practice.

No migration, no new dependency, no permission change, no new route (fields added to existing routes and to the session response).
