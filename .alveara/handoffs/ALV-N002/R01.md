## Product-owner decision made explicitly (not silently)

**Database engine: SQL Server Express for production, SQL LocalDB (same engine) for dev/test.** Discussed and confirmed with the product owner before implementation began, given the explicit tradeoff: a dental practice has multiple concurrent LAN writers (front desk, clinicians, billing) simultaneously, and SQLite serializes writes practice-wide, which is a poor fit for that access pattern. SQL Server Express is free, native to the "local Windows server" deployment target, and genuinely supports concurrent multi-client writes. PostgreSQL was also considered and rejected for lacking the native-Windows-service integration SQL Server Express offers.

## Scope

- **Persistence:** EF Core + SQL Server, one DbContext (`AlveraDbContext`), one migration (`InitialArchitecture`) applied and verified against a real SQL Server (LocalDB) database — not an in-memory provider, so real unique-index/foreign-key/transaction behavior is actually exercised.
- **Time model:** `PracticeClock` — UTC-instant vs. practice-local-wall-clock separation; explicit, non-silent handling of DST spring-forward (invalid) and fall-back (ambiguous) local times.
- **Money model:** `Money` — `decimal`-backed, USD/2-decimal-place, banker's-rounding (round-half-to-even).
- **Identity separation:** `UserAccount`, `StaffProfile`, `ProviderProfile` as three distinct, explicitly-linked entities (schema only — STORY-001/ALV-001-C01 add actual authentication).
- **Storage seam:** `IBlobStorage`/`LocalDiskBlobStorage` — generated-Guid blob identity (never a caller filename), SHA-256 integrity verification. No document module yet.
- **Backup seam:** `IBackupSnapshotProvider`/`SqlServerBackupSnapshotProvider` — real `BACKUP DATABASE ... WITH CHECKSUM`, not a raw file copy. No backup/restore story yet (`ALV-N004` consumes this).
- **Durable background work:** `BackgroundJob`/`BackgroundJobQueue`/`BackgroundJobRunner`/`BackgroundJobHostedService` — idempotent enqueue (unique `IdempotencyKey`), explicit restart-recovery (`RecoverStuckJobsAsync`), bounded retries (`MaxAttempts`), no distributed broker.
- **Measurement events:** `MeasurementEvent`/`MeasurementEventSink`/`MeasurementEventValidator` — versioned, allow-listed properties only; rejects any PHI-shaped key.
- **PHI-safe logging convention:** `PhiSafeLog.Correlate` — entity-type + id only, documented known-PHI-field-name list.
- **System Status:** `GET /api/systemstatus` (truthful app version / local-server / database / background-runner state, degrades gracefully rather than 500ing when the database is unreachable) + client `SystemStatusPage` at `/system-status`, added to the module registry, explicitly distinguishing "local server unavailable" from "public internet" state (`navigator.onLine`, with an honest caveat about what that signal actually means).
- **Server-owned database topology:** connection string lives only in server-side configuration; enforced by `tests/no-direct-db-access.test.mjs`, which also proves the client project has zero SQL/database-driver dependencies.
- **No-public-internet-dependency:** `NoPublicInternetDependencyTests.cs` source-scans the API project for any reference to a non-localhost HTTP endpoint (excluding comments) and asserts none exist.
- **Extension seams for future integrations** (FHIR/HL7, imaging, eRx, payments, claims, AI, cloud hosting): satisfied structurally, not by building unused abstractions — `IBlobStorage` is the seam future imaging/document integrations attach to; `IMeasurementEventSink` is the seam future AI/reporting integrations consume; `IBackgroundJobHandler` is an open registration point new job types (e.g. future eRx/claims polling) attach to without changing the runner.

- **Schema:** `UserAccounts`, `StaffProfiles`, `ProviderProfiles`, `BackgroundJobs`, `MeasurementEvents` tables added via the `InitialArchitecture` migration.
- **API surface:** `GET /api/systemstatus` added. `GET /api/health` (from `ALV-N001`) unchanged.

- **Security:** no authentication exists yet; `UserAccount.PasswordHash` is a reserved, currently-unused column for `STORY-001`/`ALV-001-C01` to populate. Database connection uses Windows/Trusted authentication (no password in the connection string). CORS unchanged from `ALV-N001`.
- **Config:** `ConnectionStrings:Alveara` and `PracticeTimeZone`/`StorageRoot` configuration keys added, all with safe local-dev defaults and no secrets.
- **Measurement events:** the convention itself is established by this story; no feature story has emitted an event through it yet (nothing to measure yet).

## Decisions

1. SQL Server (Express/LocalDB) over SQLite/PostgreSQL — see "Product-owner decision" above.
2. `America/Chicago` as the default practice time zone, configurable via `PracticeTimeZone` — a placeholder default since no real practice location has been specified yet; documented as configurable, not hardcoded.
3. `BackgroundJobRunner`'s core logic is exposed as directly-callable methods (`RecoverStuckJobsAsync`, `ProcessOnceAsync`) rather than only through the hosted-service polling loop, specifically so restart-recovery and idempotency are deterministically unit-testable without needing to actually kill and restart a process.
4. Measurement-event property validation uses an explicit allow-list (reject-by-default) rather than a PHI-detection deny-list, because a deny-list can never be proven complete, while an allow-list structurally cannot admit an unanticipated PHI-shaped field.
