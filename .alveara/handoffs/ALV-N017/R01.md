## Decisions and deviations
1. **The policy version rides on the security-stamp query.** The first design read the version with its own query and could not reliably meet the predeclared warm-path budget on a noisy machine (worst-of-three failed in one of two runs). The cookie check already queries the account on every request, so the version is returned by the same command and handed to the decision (`PolicyVersionHandoff`): a warm authorization costs **no database round trip of its own** (proven by counting the commands the pipeline sends). The design allowed this ("zero if folded into the existing security-stamp query").
2. **Administrator and unassigned decisions do not read the store.** The administrator always holds every permission and has no editable cells; an unassigned account none. So an administrator is not subject to the 503 of a policy outage and can repair a degraded store. The design says "then deny with 503" without singling out the administrator; **I ask the reviewer to confirm or require 503 for the administrator too.**
3. **Invalid-row reports run off the decision path** (background, one report at a time, newest snapshot wins, one query per 500 rows). A crash before a report finishes loses it until the next reload.
4. **A reload that races more than three consecutive writers is treated as an unreadable store** (stale snapshot up to 60 s, else 503), with a 5 ms pause between attempts. This fails closed.
5. **An unknown acting account id is not restricted by the target rules** in `AccountService` (every request that reaches it has an existing authenticated account; tests and jobs may pass an unknown id).
6. **The 55-minute backend ceiling in the frozen evaluator is inherited from ALV-N016.** Item 43 states no time limit and the measured history is 34.2 minutes (ALV-N016) and 53.6 minutes (ALV-N015). **Please confirm or replace it.**
7. **Performance method.** The predeclared judgement (worst of three repeats against the 1.20 ms baseline) is kept. Because machine noise alone moved a repeat by more than the budget, a same-machine A/B (the identical file on the pre-story commit and on this one, interleaved, four pairs) is supplied as additional evidence.

## Defects found by own verification
- A few of my own tests encoded wrong expectations and were corrected in the tests, not the code: the read count of the first (loading) request, the refusal types allowed in the mixed-concurrency run (an actor demoted earlier in the run is refused by the target rules), and a walkthrough assertion that a delete of the administrator is refused by the trigger (the history foreign key refuses it first).
- **Single-flight gap:** a request that read the version just before another request's reload published could start a second reload (found by a burst test that failed once in five); fixed by re-checking the published snapshot under the lock.
- **Reload livelock under a write storm** (a writer toggling with no pause starved first loads, 10 of 651 requests answered 503 at start-up); fixed with a short pause between attempts and a realistic writer in the test.
- **Invalid-row reporting cost:** one query per row made a 500-row reload take 160 ms (budget 50 ms); fixed with one query per batch and by moving it off the decision path.
- **The first version of the warm path read the version in its own query** and failed the budget in one of two runs; replaced by the fold described above.
- Existing backup-drill tests used a role-less account to administer an administrator; they now enable first and use the effective-permission service, which is what the target rules require.

## Findings in shared components
`AccountService` takes an optional `IEffectivePermissions`. Existing tests construct it through `IdentityTestHelpers`, which now supplies one. The cookie validation query returns the policy version in the same command. `Program.cs` registers the store, data source, observer, service, admin service, time provider and HTTP context accessor, and a global exception filter maps `PolicyUnavailableException` to 503.

## Limitations / debt
- No policy-write API, editor or delegation administration (ALV-N018): override and delegation rows are written by controlled SQL in tests and walkthroughs.
- Not exercised: the `admin_guard_busy` refusal of the database trigger (51208) and a deadlock victim (1205) between two raw-SQL transactions (both fail closed and leave no change).
- The two-host proof uses two hosts in one process on one database, and its outage case injects a failing data source rather than stopping SQL Server.
- A first-measured route in each fresh process is slower for its first few thousand requests (JIT warm-up); the budget evidence reflects that.
- `ChangeRoleAsync` has no non-administrator caller to test (`ManageRoles` is protected), so only the last-administrator rules apply to it.
