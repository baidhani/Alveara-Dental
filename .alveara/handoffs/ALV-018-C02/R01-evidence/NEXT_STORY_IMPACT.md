# ALV-018-C02 R01 - Next-story impact

- **Item 53, `ALV-N006` (reporting and outcome measurement):** an opening balance is an `Adjustment` ledger entry with entry number 1, the import batch id as its correlation id and the fixed reason "Opening balance migrated from an import."; a collections, production or balance report must decide how to show or exclude these (they are neither a charge nor a payment). An imported patient's registration audit entry carries the batch id as its correlation id; reports that count registrations or bookings by user should expect the importing administrator. The import tables (`ImportBatches`, `ImportBatchRows`) are available for an import-history report; their counters are the reconciliation.
- **Item 56, `ALV-N013` (Windows setup):** no new database option. The import folder (`imports`, next to the document store) must be created with the same permissions as the document store and be part of the backup the installer or the backup story takes; restoring a backup that holds import files is untested. The orphan-file sweep runs only when called (nothing schedules it).
- **Permission policy:** one new permission, `BulkImportData` (Administrator by default, grantable); a story that counts permissions or asserts the matrix must include it. Committing a balance batch also needs `ManageBilling`.
- **Test infrastructure:** the Stage 2 backend total moves from 5,334 to 5,481; the comparison script now compares test names unescaped.
- **Vendor adapters and automated external migrations** stay out of scope; the importer takes CSV only, and appointment conflicts are only ever rejected and reported.
