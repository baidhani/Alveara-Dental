## Scope delivered
- **Drafts.** A prescription is written as a draft: saved incomplete, edited while it is a draft, discarded (kept, never deleted). It is the only mutable record of the workflow; the database refuses deleting a draft, changing a finalized or discarded one, and changing its patient, create key or the prescription it amends.
- **The allergy and medication lists the prescriber saw.** A draft keeps a snapshot of the active allergies and current medications and how far each list can be relied on, as the prescriber last acknowledged. Editing never refreshes it. When the lists change, the draft shows what changed in words and finalizing is refused (409 `safety_context_changed`) until the prescriber presses "I have read the changes"; the acknowledgement carries the fingerprint the screen showed, so only what was on screen can be acknowledged.
- **Finalization.** STORY-016's allergy check and review rule run unchanged on the draft's entry (the rules are called, not copied), plus the instructions, the quantity with its unit and the refills are required. The prescription, its details, its Finalized event, the draft's closing, for an amendment the original's Superseded event, and the PHI-free audit entry are written in **one save**: if the log fails nothing is saved. An unreadable safety context refuses the save (the check is never skipped). A confirmation shows exactly what will be recorded before anything is saved.
- **Lifecycle.** A finalized prescription is never edited or deleted: it can be cancelled or discontinued (a reason is required and kept with the event, never in the log), amended (a new draft that replaces the original only when finalized; the original is marked Superseded and stays as it was) and printed. The status is worked out from the events; at most one ending event is possible (a unique index) and a prescription is finalized once.
- **Print.** The server builds the print content from the immutable record with a content hash, records that it was prepared (who and when; never the contents) in the same save, and refuses when the log cannot be written (`print_failed`). A prescription saved by STORY-016, which has no instructions, quantity or refills, answers `print_incomplete` and is amended by filling in the rest.
- **No unsupported decision support.** There is no drug-knowledge source. The options say `decisionSupportConfigured: false`, a banner says so permanently, and every check result and every print carries the statement; the quantity and refill ceilings are described as typing-error ceilings, not clinical or legal limits; a test pins that no method of the workflow is named for interactions, appropriateness or therapeutic checks.
- **Surfaces.** 15 routes in `PrescriptionWorkflowController` (reads need `ViewPrescriptions`; every change needs `ManagePrescriptions` plus a CSRF token); a new "Prescription composer" tab (composer, persistent safety panel, finalization confirmation, record list with actions, print preview).

## Decisions and deviations from the prompt's wording
- **The Prescription composer is a second tab, not a replacement of STORY-016's Prescriptions tab.** STORY-016's contract is immutable and its real-browser spec drives the original form, so the quick entry stays. The cost is two ways to prescribe on screen; retiring the quick form means rewriting STORY-016's tests and is a decision for the reviewer or a later story.
- **Amendment is a new record that supersedes the old one**, not an edit; "correction" of a finalized prescription is therefore an amendment. The prompt's "draft/finalized/cancelled-or-discontinued lifecycle as supported" is implemented as drafts, finalization and the three ending events (Cancelled, Discontinued, Superseded).
- **The configured policy for an allergy conflict** is STORY-016's rule, documented as the default: a match, or a list that is not established, needs the prescriber's own words; there is no separate configuration surface (none was asked for and a second policy source would be invented).
- **Printing is a logged read** (`GET .../print` writes an audit entry); if the entry cannot be written nothing is returned.
- **Quantity and refill ceilings (1000 and 12)** are typing-error ceilings chosen like the dose ceilings, not clinical or legal limits; no controlled-substance or jurisdiction rule is modelled.
- **Duplicated sentences.** The two allergy-review refusal messages appear in the finalize service as well as in STORY-016's service, because STORY-016's service was left untouched.

## Defects found by this attempt's own verification
- Schema: my first check constraints compared two boolean expressions with `=`, which is not valid T-SQL; SQL Server rejected the migration and every schema test failed at once. Rewritten with explicit AND/OR before any commit.
- `ef migrations remove --no-build` removed the pushed `AddPrescriptions` files instead of this attempt's migration; restored from git and verified unchanged.
- Negative controls found four test gaps of my own, closed with tests: a finalized draft could be discarded without a test failing; the CSRF test omitted the check, acknowledge, discard and discontinue routes. One equivalent mutant is documented (`docs/testing/PRESCRIPTION_WORKFLOW_NEGATIVE_CONTROLS.md`).
- The acceptance item about current medications and ALV-N011 alerts being visible had code (the shared safety panel) but no test: a component test and real-backend assertions were added before packaging.
- The real-browser run of STORY-016's own screen had earlier found a dark-mode contrast defect and a doubled sentence; both fixed (recorded in STORY-016's evidence, not part of this attempt).

## Findings in shared components of completed stories
- **`CompletedProcedureServiceTests.Two_overlapping_sets_submitted_at_once_leave_exactly_one_winner_and_each_procedure_completed_once` (ALV-008-C01) is intermittent.** It failed once in the full run with a SQL Server deadlock victim ("Transaction (Process ID 68) was deadlocked ... chosen as the deadlock victim"), passed 5 of 5 isolated reruns and in the whole 19-test `CompletedProcedureServiceTests` class run afterwards. The test races two completions on purpose; the service surfaces the deadlock as an error instead of retrying it. No Treatment or Odontogram file is changed by this attempt, so it is disclosed, not fixed (outside this story's scope). The reviewer may want a retry-on-deadlock in the completion service.
- `PrescriptionException` (STORY-016) gains an optional `Detail`; no behaviour of STORY-016 changed.
- The patient workspace tab registry gains one entry; its route test's exact tab list was updated.

## Limitations / debt
- No drug interactions, no clinical dose or quantity appropriateness, no eRx or pharmacy connectivity, no controlled-substance rule, no encounter linkage (the prompt's out-of-scope list).
- Two prescribing tabs coexist (see decisions).
- **File size.** `PrescriptionWorkflowServiceTests.cs` (583 lines) is above the 500-line ceiling and `PrescriptionWorkflowSchemaTests.cs` (491) and `DraftComposer.tsx` (341) are above the 300-line target; the ceiling concerns files that are touched again, and the next change to either should split it.
- The safety snapshot is stored as text (`nvarchar(max)`) so a long list cannot break finalization; its fingerprint is what is compared.
- Amending a prescription that has an open amendment returns that draft rather than starting another.
- The reviewer's browser walkthrough covers Chromium only (the project's real-backend specs run Chromium).
