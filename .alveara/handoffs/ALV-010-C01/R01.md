## Scope delivered (the prompt's implementation scope)
- **Library views and filters** - filters by category, encounter, tooth, oral region, date range, a word of the file name or description, and Active/Inactive/All; a List or Thumbnails view; Preview for pictures; details with the history and every inactivation.
- **Thumbnails** - the browser scales the original (PNG or JPEG up to 5 MB) behind a stable `/thumbnail` route, not logged; anything else gets a word. No image library was added.
- **Metadata** - the document's encounter and one tooth (FDI key) or one oral region, never both; editable like the category; wrong values refused field by field; the encounter must belong to the same patient (service and database).
- **Inactivation, not deletion** - Admin and Office manager can make any document inactive with a required reason and make it active again; it leaves the default library and the duplicate check; the append-only `DocumentStatusChanges` keeps who, when and why; the reason never reaches the log or the events.
- **Storage integrity** - opening checks the file exists and has the recorded size (`file_missing` 404, `file_corrupt` 409, nothing served); an on-demand check of every stored file (or one) records Ok, Missing or Corrupt per document in its own table so a check never changes a document's row version.
- **Unreferenced files and import recovery** - a stored file nothing points to (for example after a process died between the write and the commit) is listed only when older than an hour, then removed only after an explicit selection and confirmation, by Admin or Office manager (`ManageDocumentStorage`), re-checked under a lock, logged before deletion, at most 500 at a time; never automatic.
- **Import hardening** - the safety matrix of names, types and content (61 cases) confirmed and guarded; the duplicate check ignores inactive documents; upload progress and Cancel on the screen.
- **Backup and restore** - restore validation now requires every restored document's file in the backup with the recorded size and hash (a real gap: a backup lacking the files was previously trusted); the drill proves documents survive.
- **Signed forms** - the library lists signed forms read-only; a later template edit or inactivation changes neither snapshot nor hash (one test added); form templates are administered where they were (linked from Document settings).
- **Storage page** - `/admin/document-storage` (counts of intact, missing, damaged and unchecked files, files that need attention, unreferenced files with selection and confirmation).
- **Test infrastructure** - the document and API tests no longer leave storage folders behind.

## Decisions and deviations from the prompt's wording
1. **Thumbnails are browser-scaled for now** (owner decision): no image library or dependency; server/desktop thumbnails later behind the same route.
2. **Unreferenced files are reported, then removed after review** by Admin or Office manager (owner decision), never automatically.
3. **Inactivation is held by Admin and Office manager for any document** (owner decision); there is no separate "responsible provider" owner field.
4. **Form/template administration is reused, not rebuilt.** The prompt asks for template administration that reuses ALV-N010 semantics; ALV-N010's form-template screens already provide it, so Document settings links to them and the signed-snapshot and history view is the existing read-only signed copy. No new form administration was built. This is the largest reading of "extend/configure form templates" left to the reviewer.
5. **The encounter picker reads a documents-scoped list.** Importers hold `ViewDocuments` but not the right to read clinical encounters, so the picker used to be empty for them; the new list returns an id, a date and a state only.
6. **The integrity result is its own table** so a check never bumps a document's row version.
7. **Restore validation was strengthened** (new check) because the old restore trusted a backup that lacked document files.
8. **The tooth shown in the screens follows the odontogram's default numbering** (Universal), stored as an FDI key.

- Integrity columns on `Documents` would have changed the row version on every check; moved to their own table (migration regenerated while unpushed).

- Restore trusted a backup missing document files (closed by the new check).

- The document tests (from STORY-010 on) left about 3,500 storage folders and the API tests a shared folder of 900 files; fixed and now flat.
