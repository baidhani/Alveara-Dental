## Disclosures
- **Q-5ag "performed by" is not built.** The owner decided this (2026-11-19) and review ADDENDUM-02 requires it to be carried forward: billing views never show the performing provider (the ALV-007-C02 R02 rule). This supersedes briefing R02 section 1 item 7, S8, C8 and the section 6 row that names performedBy.
- **The READCOMMITTEDLOCK rationale was corrected** (addendum 02). Control (f), with the hint removed, passed the 20-round direct race. The hint stays; its necessity is not claimed; the guarantee rests on the per-payment lock and 51295.
- **Control (a)** fails at the preview step, so it proves the tests detect the removal rather than the trigger alone. 51295 on its own is proven by the direct-SQL migration tests.
- **Control (e)** first ended each test on the database exception before its counts. The tests were strengthened (invariants before the refusal code; test-only) and re-run (addendum 02); `control_e.log` holds the re-run only.
- **The replacement reason travels with the issue request,** not inside the preview token (the token limit is 600 characters and a reason can be up to 500). The token binds which receipt is replaced.
- **Server money format in notes:** one line was changed in slice 5 so that notes match the client's `formatMoney` exactly (no thousands separator). It is covered by the sweep (338/338).
- **Own test mistakes on first runs, fixed in the tests and not the code:**
  - unfunded accounts in the raw-row tests;
  - a v1 receipt fixture that wrote a silent second receipt (now a replacement);
  - tests hard-coding current version 2 or the old CSV layout;
  - record equality over lists in a new test;
  - in the browser spec: duplicate patient details (the duplicate check answered 409), an ambiguous Close button, a too-wide row match, a regex escape.
- **F-207, F-196 and F-195** are shown by code and screenshots, without a dedicated assertion.
- **Specs updated in source and not run:** `billing-ledger-real-backend`, `billing-statements-real-backend`.
- **Leftover test data:** one `AlveraTest_*` database and one Temp template backup existed before this story. The counts are identical before and after; they were not removed.
- **Dev database:** `AlveraDev` does not have the new migration (not migrated without the owner's permission).
- **Tooling:** Vitest was run from PowerShell (on this machine, launching it from Bash intermittently fails to load its runner).
