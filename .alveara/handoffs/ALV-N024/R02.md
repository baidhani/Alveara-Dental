## CR-1: the payer rule is identical at every enforcement layer
**Owner decision (2026-11-19), the review's default: "Active only".** Besides the patient, a payer must be an **active** patient who is the registered guarantor, a member of the patient's recorded household, or recorded as responsible for the account. This is the rule in:
- the screen: the payer list comes from the server;
- the service: `EligiblePayersAsync` / `payer_not_eligible`, unchanged from R01 and already active-only;
- the database: 51142, **changed**. The trigger refuses a non-patient payer who is inactive or unrelated.

This narrows the old ALV-007-C01 rule, which accepted an inactive recorded-responsible party. Stored rows are never re-checked (the trigger checks inserted rows only). The migration `20261119034014_AddReceiptReplacementAndPayerEligibility` was corrected **in place**: it has never been applied outside test clones (`AlveraDev` does not have it), so no second migration was added. Its Down still restores the original ALV-007-C02 trigger body.

**The F-196 browser check found a real defect.** The R01 CSS (`.alv-bill__choose { display: flex; ... }`) was overridden by the more specific shared rule `.alv-dx__form label { flex-direction: column }` (Diagnosis.css). The checkbox (13 x 13) was still centred **above** its text: the first run failed at 12.25 px off-centre (`artifacts/walk_integrity_failed_diagnostic.txt`). This was diagnosed by recording the geometry, not by loosening the check. It was fixed with `.alv-dx__form label.alv-bill__choose { flex-direction: row; justify-content: flex-start; align-items: center; }` in `Billing.css`. On the final run the checkbox is at x 281 and its text starts at x 296, on one 22.5 px line (`checkbox-geometry.json`). R01 had recorded F-196 as "shown by code and screenshots"; that was wrong, and the R01 evidence row is superseded by this proof.
