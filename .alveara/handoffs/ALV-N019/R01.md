## Decisions and deviations from the approved brief
1. **No chain-only clock host / injected clock** (O-1 conditional, PD-32): stage 0 needs no clock. `clockMode` is recorded as `real`. The clock-seam test in the brief (`clock-seam.txt`) was therefore not built.
2. **`playwright.config.ts` `testIgnore` not edited**: `chain/` is outside that config's `testDir` (`./e2e`). `vitest.config.ts` exclude was extended instead (a real regression caught by `tests/gate-tooling-coexistence.test.mjs`).
3. **S-01..S-08 refusal tests** live in `tests/stabilization/dev-script-refusals.test.mjs` and cover S-01 (busy 5072), S-02 (busy 5173) and S-06 (missing database) by stubbing the port and SQL checks in a temporary copy. S-03, S-04, S-05, S-07 and S-08 have no separate test; the runner's own create and drop of `AlveraChain_<id>` is exercised by every stage-0 run.
4. **F-003 injection tests:** the user-controlled inputs of merge and unmerge are Guids and cannot carry text, so no injection payload can be sent through them. The tests pin the catalog and quoting boundary instead (`PatientMergeSqlBoundaryTests`).
5. **F-002:** the guard removes a compiler warning and does not change behaviour (SQL never matches NULL in that query); a regression test records it. No honest negative control exists.
6. **The runner self-test in the brief** (kill the API mid-run and assert cleanup; refuse an existing database; label a dirty tree) is only partly covered: the safety-gate tests cover refusals and containment; `implementationSha` gets a `+uncommitted-changes` suffix on a dirty tree (not unit-tested); "kill mid-run" is NOT tested.
7. **E10:** the checkpoint is written and `RESTORE VERIFYONLY` passes. That the live database is unchanged by it is not separately asserted.
