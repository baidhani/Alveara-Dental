## Decisions and deviations from the approved brief
1. **Chain host design:** a `WebApplicationFactory<Program>` on Kestrel with a startup filter, as O-1 describes (separate host, production `Program.cs` unchanged). The chain host differs from production by exactly the clock registration and one route.
2. **Mode detection by content, not by 404:** the production application answers an unknown GET with its client page (200 HTML), so a 404 does not identify production; only a JSON body with a `mode` field counts as the chain's report. (Found by my own test on the first run.)
3. **No communication stubs:** the only notifier in the application, `FileDropBackupNotifier`, writes to a local folder and makes no external call, so there is nothing to stub. Stated, not built.
4. **S-03, S-04, S-05, S-07, S-08** still have no separate tests (S-01, S-02, S-06 are tested); the runner's own create and drop of `AlveraChain_<id>` is exercised by every run.
5. **A hard kill of the runner process itself** cannot run its cleanup and is not covered; a leftover would carry the `AlveraChain_` prefix.
6. **F-002** has no negative control (the guard is behaviour-neutral); it keeps its regression test.
7. **F-004** (node/npm version recording) is not separately reported beyond the register row.
