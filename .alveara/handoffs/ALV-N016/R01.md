## Scope delivered
- **`TestDatabaseTemplate`** (test project): builds one fresh template per process with the real EF migration path, verifies its applied migrations equal the code's and `READ_COMMITTED_SNAPSHOT` is on, reads the logical file names from the backup (`RESTORE FILELISTONLY`), backs it up and drops it; restores a unique clone per ordinary fixture with `WITH MOVE`; rebuilds if the code's migration list no longer equals the template's; caches a build failure and raises `TemplateBuildException` for every fixture (never a fallback); reports earlier leftovers (backups and `AlveraTemplate_*` databases) and never deletes them; removes its backup when the process exits; writes one structured JSON event per occurrence (to stderr and, when `ALVERA_TEST_TEMPLATE_TELEMETRY` names a file, to that file) with the template's `role`.
- **`TestDatabaseFixture`**: an ordinary fixture restores a clone; a restore failure removes the partial clone, logs a safe `template_restore_fallback` event (a class or a SQL error number only) and falls back to the unchanged create-and-migrate path for that fixture; retries, failed-initialisation cleanup, pool release and file-location protection are unchanged.
- **Named inventory**: `RealMigrationTestDatabaseFixture`, `[RealMigrations]` and `RealMigrationInventory` keep the real path for 19 classes: 15 that roll the schema back and forward (`BillingRefundMigrationTests`, `CompletedProcedureMigrationTests`, `CompletionAdoptionSchemaTests`, `CompletionChartEvidenceTests`, `DiagnosisMigrationTests`, `DiagnosisStructureMigrationTests`, `DocumentLibrarySchemaTests`, `DocumentSchemaTests`, `MigrationTests`, `MigrationUpgradeTests`, `OdontogramCatalogueMigrationTests`, `PerioMigrationTests`, `PrescriptionSchemaTests`, `PrescriptionWorkflowSchemaTests`, `TreatmentPlanRevisionMigrationTests`) and 4 that test the fixture itself (`TestDatabaseInitFailureCleanupTests`, `TestDatabaseLocationTests`, `TestDatabaseTeardownTests`, `TestDatabaseTransientRetryTests`); `MigrationFailureTests` builds its own database and is named separately.
- **Tests**: `TestDatabaseTemplateTests` (13) and `RealMigrationInventoryTests` (5).
- **Frozen Stage 2 tooling** (`R01-evidence/stage2/`): `run_stage2.sh`, `evaluate_stage2.py`, `compare_outcomes.py`, `leak_counts.sh`.

## How the acceptance criteria are met

## Decisions and deviations
1. **The bypass is by class, not by test.** xUnit builds the fixture before a test method is known and the Stage 2 comparison requires unchanged test ids, so a test cannot be moved to another class. A class that contains any rollback test therefore keeps the real path for all of its tests (293 tests in the 19 classes, of about 3,200 database tests); that costs part of the speed-up and is the price of keeping the real migration and rollback path named and exercised.
2. **A clone keeps the template's logical file names and has its own physical files.** No test or production code depends on logical names; the clone-equivalence test compares every database setting and the whole schema, trigger bodies and seeded row counts instead.
3. **Telemetry has a `role`** so the evaluator can count the run's own fallbacks and ignore the ones the template tests inject on purpose.
4. **`ALVERA_TEST_TEMPLATE=off`** exists as a measurement switch (the A/B above) and is checked as unset by the Stage 2 evaluator.
5. **Cleanup is at process exit.** A killed host leaves its backup, which the next run reports and does not delete.
6. **The expected Stage 2 test count is 4,318** (4,300 plus the 18 new tests); the ceiling and every other threshold live only in `evaluate_stage2.py`.

## Defects found by own verification
- The first run of the template tests failed in their own cleanup (they disposed fixtures that had never initialised or were already disposed); fixed in the tests.
- The telemetry of a run mixed its own fallbacks with the ones the template tests inject; fixed by the `role` field.
- The Stage 2 comparison script first reported 1,990 missing ids because it unescaped names that the baseline file keeps escaped; found by testing it against the baseline itself and fixed.
- A mutation of the leftover cleanup did not compile on the first try; redone and caught.

## Findings in shared components
`TestDatabaseFixture` is no longer `sealed` (its real-migration subclass needs it); the public parameterless constructor now restores a clone. `SafetyTestBase` chooses the fixture by the `[RealMigrations]` attribute. Existing test classes outside the inventory are untouched.

## Limitations / debt
- Stage 2 has not been run: the 55-minute ceiling and the unchanged-ids rule are unproven until it is.
- The A/B timing is a 273-test sample on one machine and may not extrapolate; the earlier unmeasured projection was 35 to 45 minutes for the full run.
- The focused regression covers 444 tests in 37 classes, not the whole suite.
- Parallel execution, shared databases and SQL tuning are out of scope.

## Unresolved questions
- Should the 19-class bypass be narrowed later by splitting rollback tests into their own classes (a change of test ids, which this story forbids)?
- Should the template backup survive across runs when the migration list is unchanged (it would save about 5 s per run and reintroduce a stale-backup risk)?
