## Scope delivered
- **Schema** (migration `AddNotificationCenter`): `Messages`, `MessageRecipients`, `Notifications`, `NotificationCursors`; check constraints (priority, kind, shape, subject 120, body 2000 not blank, no NUL, source-key characters, times); filtered unique indexes `(RecipientUserId, SourceKey)` and `(MessageId, RecipientUserId)`, unique `(SenderUserId, IdempotencyKey)`; eight triggers (51195 to 51202) making messages and recipients append-only, notifications changeable only by a one-time read and a one-time hide (never hide unread, never delete), the cursor forward-only; rollback guard 51203; the cursor starts at the document-events high-water mark (no back-fill).
- **Permissions**: `SendMessages`, `ReceiveDocumentNotifications`, `ViewNotificationAuditHistory`, `ViewMessageAuditContent` in the fixed matrix.
- **Services**: `NotificationService` (summary, lists, read, read-all, hide, clear history), `MessageService` (send with idempotency, validation, rate limit 30 a minute, recipients, reply, thread, inbox and sent, receipts), `NotificationLinkService` (server-side patient link), `NotificationAdminService` (metadata history; break-glass for one message or thread, attempt audited first, success audited before content, audit failure returns no content), `NotificationConsumer` plus `NotificationConsumerHostedService` (durable cursor, same-transaction advance, `Notifications:ConsumerPollSeconds`, default 5, 0 off).
- **Controller** `NotificationsController` (16 routes, CSRF on every write).
- **Client**: bell and Important/Urgent banner in the shell (60 s poll and on focus, "could not check" instead of zero, dismissible, generic text), `/notifications`, `/messages`, `/messages/:id` (compose, reply, thread, sent, receipts, patient link), `/admin/notifications` (metadata history, break-glass form), typed `notificationsApi.ts`.
- **Tests and walkthrough**: schema, permission, API, client and a real-backend walkthrough (below).

## Decisions and deviations
1. Consumer is a hosted service inside the API process (the owner's decision), polling every 5 s; delivery is eventually consistent.
2. Rate limit is 30 messages a minute per sender, counted from stored messages (owner's decision).
3. Priorities are open to every sender with `SendMessages` (no separate urgent permission), per the prompt.
4. Replying asks the writer to pick recipients again; a reply is not auto-addressed (the message view does not carry the sender's user id, by design, so the client never holds ids it does not need).
5. The compose screen has no patient picker. A patient link can be set through the API (and is exercised by the walkthrough); a screen-level picker is not delivered.
6. The matrix proof count grows with the four new permissions (ALV-N017's proofs are generated from the enum).

## Defects found by own verification
- (R02) The R01 notification list returned the message subject (finding ALV-N015-R01-01); fixed as above. My R01 test positively asserted the subject, so the defect was encoded in the tests; the test is replaced by a raw-JSON privacy test with a negative control.
- Message body constraints let a whitespace-only CRLF body and a NUL through; added `NotBlank` and `NoNul` (model, migration, designer, snapshot consistent).
- The real-backend walkthrough found a client race: a slow answer for the Unread tab replaced the History list. Fixed with a latest-request guard on the notifications and messages lists; reproduced by a unit test that fails without the guard.
- The walkthrough's accessibility scan found a dark-theme contrast failure on plain links; fixed with the information colour used elsewhere (`Notifications.css`).
- Two walkthrough assertions were wrong (audit scan too broad; an already-read banner) and were corrected in the spec, not in product code.

## Limitations / debt
- The message **inbox and sent lists** (`GET messages`) still show a message's subject to its sender and recipients, because they are the participants' own mailbox on an authorized message route; the notification list does not. If the reviewer wants the inbox list reduced too, that is a further change.
- The banner renders at the bottom of the sidebar, not across the top of the page; on a short window it may need scrolling. The Unread/History tabs use unstyled buttons.
- No test removes `ReceiveDocumentNotifications` between two events; the rule (recipients resolved when the event is processed) is in code and covered only for the current matrix.
- Crash recovery is proven by replaying the whole history after resetting the cursor, not by killing a process between the notice insert and the cursor advance (they are one transaction).
- The "recipient may not view patients" refusal cannot be reached through the API because every role in the matrix holds `ViewPatientRecords`; the single `patient_access_denied` answer is tested for the no-link case.
- The cursor trigger is disabled in one test to reset the cursor (test only).
- Lint reports warnings (set-state-in-effect on list pages, as elsewhere in the app), exit code 0.
