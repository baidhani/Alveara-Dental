## Corrections made this attempt

### ALV-N009-R02-01 — sliding cookie renewal disabled at the root

`src/Alveara.Api/Program.cs`'s cookie-auth configuration now sets `options.SlidingExpiration = false` explicitly. ASP.NET Core's default (`true`) silently renews `ExpiresUtc` on any authenticated request past the renewal midpoint — including the R02 poll, which exists purely to *observe* session state, not to represent genuine user activity. With sliding renewal off, the `ExpiresUtc` set once at sign-in (`AuthController.SignInAsync`, using the account's `SessionTimeoutMinutes`) is a fixed, honest deadline no amount of background polling can extend. This is a server-side fix, not a client-side workaround — it protects the invariant regardless of what future client code polls this endpoint.

New backend test (`AuthControllerPermissionMatrixTests.cs`, `GET_permissions_does_not_extend_the_session_expiry_on_repeated_calls_SlidingExpiration_is_off`): calls `GET /api/auth/permissions` four times in a row (mirroring exactly what the poll and focus/visibility handlers do) and asserts the server-reported `sessionExpiresAtUtc` is byte-identical every time. Deterministic and fast — no real elapsed time needed, unlike testing an actual timeout expiry.

### ALV-N009-R02-02 — monotonic request-generation ordering guard

`AuthContext.tsx` gained a `requestSeqRef` (a `useRef` counter): every `refresh()` call increments it and captures its own value at the start; the response is only applied (`setState`) if that captured value still matches the ref's current value when the response arrives. `logout()` and the reactive-401 handler (`setUnauthorizedHandler`'s callback) both increment the ref synchronously, before any `await`, so any refresh already in flight at that moment is retroactively invalidated no matter how it eventually resolves.

This is a general concurrency invariant ("only the most recent decision can ever win"), not a fix narrowly scoped to the reviewer's exact probe — it protects every current and future caller of `refresh()` (poll, focus, visibility, expiry boundary, post-login/MFA) against every pairwise ordering, not just the one the reviewer happened to construct.

Two new deterministic tests in `AuthContext.test.tsx`:
- An older `refresh()` call is left pending while a newer one resolves immediately with a 401; the older call's later successful resolution is proven not to resurrect `signed-in` state.
- An older `refresh()` call is left pending while `logout()` completes; the older call's later successful resolution is proven not to undo the explicit sign-out.

This is the correct tradeoff for a deterministic, security-honest timeout (and was one of the review's own explicitly acceptable designs), but it is a behavior change worth the reviewer's attention: session length is now a hard ceiling from sign-in, not an idle timer.
