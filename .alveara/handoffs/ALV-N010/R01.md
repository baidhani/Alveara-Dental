## Scope delivered (implementation scope of the prompt, item by item)
- **Versioned form/template definition model** — `FormTemplate` (stable key, category, active flag, current version) and immutable `FormTemplateVersion` rows (title, wording, field definitions, SHA-256 content hash). Editing publishes a new version (guarded by the template's row version); unchanged content publishes nothing.
- **Initial categories** — Privacy, Financial, General consent, Treatment. No wording is shipped and none is claimed legally complete; the UI and `docs/FORMS_AND_CONSENTS.md` say so.
- **Patient/staff-assisted completion** — `PatientForm` drafts with typed answers (checkbox, short/long text, choice, date; required flags), pinned to the template version they started on.
- **Signer identity/relationship, timestamp and signature capture metadata** — signer name (free text, not necessarily a registered patient), relationship (Self, Parent, Legal guardian, Spouse, Legal representative, Other + description), signature method `typed-name` + typed text, the attestation text agreed to, time, and the capturing staff member.
- **Immutable signed snapshot** — `SignedFormSnapshot` holds a verbatim copy of the version's wording/fields, the responses as saved at signing, the signer data and a SHA-256 over all of it; one per form (unique index); never updated or deleted (application guard **and** database triggers).
- **Template edits create a new version and never alter prior signed snapshots** — proven in unit/integration tests and in the real browser (two further versions published after signing; wording and fingerprint unchanged).
- **Form status/history and controlled void/inactivation/correction** — `Draft` / `Signed` / `Void`; append-only `PatientFormEvent` history (Started, Signed, Voided, Superseded); void requires a reason and, for a signed form, `VoidForms`; correction = void + a new form; templates can be inactivated/reactivated (existing forms unaffected).
- **Extension seam for the document library** — `PatientFormReader.SignedDocumentsAsync` / `GET /api/patients/{id}/signed-documents` return read-only `SignedFormDocumentDescriptor`s (no answers).

UI deliverables: Form Templates administration; the patient workspace **Forms** tab (list with status in words, start, draft editor); a **pre-sign review** screen; the **signed copy + history** view; status always spelled out ("Draft - unsigned", "Signed", "Void (was signed)").

## Architecture / schema / API / UI / security / config / measurement changes
- **Schema** — migration `AddVersionedForms`: `FormTemplates`, `FormTemplateVersions`, `PatientForms`, `SignedFormSnapshots`, `PatientFormEvents`. Unique indexes: template key; (template, version number); one signed snapshot per form; **one open draft per patient per template** (filtered). All foreign keys `Restrict`. Two hand-added `INSTEAD OF UPDATE, DELETE` triggers (`TR_SignedFormSnapshots_Immutable`, `TR_FormTemplateVersions_Immutable`, error numbers 51010/51011). `FormTemplates.CurrentVersionId` is deliberately not a foreign key so a template and its first version commit in one save.
- **API** (`FormsController`) — `GET|POST /api/forms/templates`, `GET /api/forms/templates/available`, `GET|PUT /api/forms/templates/{id}`, `PUT …/active`; `GET|POST /api/patients/{id}/forms`, `GET /api/patients/{id}/signed-documents`; `GET /api/forms/{id}`, `PUT …/responses`, `POST …/restart`, `POST …/sign` (requires `Idempotency-Key`), `POST …/void`. Stable error codes: `validation_failed` (+`fieldErrors`), `template_key_taken`, `template_not_found`, `template_inactive`, `patient_not_found`, `patient_inactive`, `form_not_found`, `form_not_draft`, `form_void`, `already_signed` (+`existingId`), `template_version_mismatch`, `idempotency_key_required`, `void_not_permitted`, `row_version_required|invalid`, and the shared `concurrency_conflict`.
- **Security** — four permissions appended to the enum (`ManageFormTemplates`, `CompleteForms`, `ViewSignedForms`, `VoidForms`); grants in `docs/FORMS_AND_CONSENTS.md`. Every state-changing call needs CSRF; the server re-checks every permission. Signing and void reasons are never in the audit log.
- **Audit** — `FormTemplateCreated`, `FormTemplateVersionPublished`, `FormTemplateStatusChanged`, `PatientFormStarted`, `PatientFormSigned`, `PatientFormVoided`: actor and time, template key + version only; staged in the same save as the change (a failing audit write rolls the whole signature back - tested).
- **Measurement** — `form.signed` (schema v1; `category` ∈ privacy/financial/general_consent/treatment, `outcome` = success) through the shared privacy-safe sink; a failure to record is logged and never undoes a signature.
- **UI** — routes `/patients/:id/forms`, `/patients/:id/forms/:formId`, `/admin/form-templates`; nav entry "Form Templates"; tab added through `patientWorkspaceTabs` (the first module to use the ALV-003-C01 extension point). A form id under the wrong patient is never shown. Unsaved-change protection on the draft and template editors.
- **Config** — none new; `playwright.forms.config.ts` for the real-backend walkthrough (excluded from the default mocked run).

## Decisions and deviations from the prompt's wording
1. **Draft stays on its starting version** ("template changes during active completion"): a newer version is offered, never forced; moving voids the old draft as "replaced" and carries over every answer that still fits (same id and kind; a choice must still be an option).
2. **Signer is free text plus relationship**, answering the question the `ALV-003-C01` handoff left open (a signer need not be a registered patient). The signature is a typed name plus an explicit attestation tick; no drawn signature.
3. **Signing binds to what was reviewed**: the request echoes the draft's row version and the template version id the user saw; a draft changed after review is a 409, not a signature on different answers.
4. **Role grants are my judgment** (the plan names permissions, not roles): staff who see patients complete and view forms (front desk, dentist, hygienist, assistant, office manager); billing may *view* signed forms only (financial forms); only the office manager and admin administer templates or void a signed form. Front desk can discard a draft but not void a signed form.
5. **Immutability is enforced twice** (application guard + database triggers) because a signed record that a console script could alter is not trustworthy. Consequence: a future migration that must alter these two tables has to drop and recreate the triggers deliberately.
6. **An inactive patient cannot have a new form started**; their existing forms stay readable.
7. **Template key and category are fixed after creation** (an edit changes title, wording and questions).
8. **No success toast** (see finding F1 in `ALV-003-C01`): saves are confirmed inline.
