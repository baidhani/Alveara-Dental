## The correction (CR-1)
1. **Database-enforced guard.** Migration `20261117160917_AddDiagnosisFinalizedEncounterGuard` adds trigger `TR_Diagnoses_EncounterNotFinalized` on `Diagnoses`, **AFTER INSERT only**. It reads the linked encounter `WITH (UPDLOCK, HOLDLOCK)` (a locking read of the latest committed row, held to the end of the insert's transaction) and throws 51287 when it is Finalized. A finalize in flight makes the insert wait and then refuse; a finalize that comes second waits until the diagnosis is committed (recorded while a draft). Down drops the trigger; no table, column, data or model change (EF snapshot unchanged).
2. **Only new inserts.** Corrections and withdrawals are UPDATEs and are unaffected; existing rows are not re-checked. The same-patient and immutable-link protections stay in `TR_Diagnoses_Links` (51073/51074), unchanged.
3. **Mapping.** `DiagnosisService` maps 51287 to the same 409 `encounter_finalized` as its up-front check (one helper); no SQL text or PHI reaches the caller. Same-key replay still returns before any write.
4. **Only insert path.** `DiagnosisService.RecordAsync` is the only code that inserts diagnoses (merges update `PatientId`; backup restore is database-level; imports do not touch diagnoses) - verified by search, so no legitimate path is blocked.
5. **Unchanged:** completion, adoption and amendment attribution (ALV-008-C01 D6), documents/referrals, signed drafts.
