## What changed
1. **Encounter writes go to the chart (OD-01, OD-02).** For Allergy, Medication and MedicalHistory, the encounter's add, change, status, remove and section-statement actions call `ClinicalRecordService` with the encounter's id. The item version and the statement event carry `EncounterId`; the encounter is touched in the same save (its version moves, so a stale encounter editor is refused) and gets a PHI-free history row. Dental history keeps the encounter's own entries (BR-3).
2. **One record per allergy (Addendum 02).** New allergy names are trimmed and inner whitespace collapsed, case kept. A match is refused with 409 `duplicate_item` carrying `existingItem {id, kind, status}`: Active -> "Update that item instead"; Resolved/Inactive -> "with status X. Reactivate or update that item instead". The status is chosen by the user (none preselected; a missing status is refused); cancel changes nothing; concurrent adds leave one record. A same-values retry is a quiet replay.
3. **Medication / medical history already on the chart (S-1 option A).** The same 409 points to the item; the encounter offers "confirm the list is current" (new route) or update. Normalization stays allergy-only (BR-4).
4. **None reported (OD-04).** Refused only while an ACTIVE item exists (`section_has_active_items`); "unknown" keeps the empty-section rule. Adding an item, or reactivating one, withdraws a "none known" and records that it did.
5. **Encounter read path (brief 4.2).** Each chart-backed section shows the chart now, "recorded on the chart in this encounter" (from the append-only versions), the statement made here (with who and when), and pre-A1 entries and marks read-only (`legacy_entry_read_only`). A contradiction - a legacy mark, this encounter's "none known" or the chart's "none known", for a section with an active item when said or now - is computed on read, shown, never stored or erased.
6. **Encounter removal** only for an item added in that encounter, kept as entered in error with a reason (`item_not_added_here` otherwise; logged assumption 1).
7. **One banner (OD-05).** The encounter's second safety strip is removed; every safety-relevant clinical write goes through `withSafetyNotice`, which tells the patient header banner to refetch; a repo guard refuses an unwrapped or bypassing write.
8. **Routes.** New: `POST api/encounters/{id}/entries/{entryId}/status`, `POST api/encounters/{id}/sections/{kind}/confirm-current` (ManageClinicalNotes, CSRF). Existing request bodies gained optional `itemRowVersion` and `reason`. Error bodies gain `existingItem` only on `duplicate_item`.

No migration (Step 0 section 5: the `EncounterId` indexes already exist; `has-pending-model-changes` reports none), no new dependency, no permission change.
