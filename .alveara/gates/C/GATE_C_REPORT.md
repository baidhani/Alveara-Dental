## Disclosures

- **Reuse of the backend run (reviewer judgement).** The full backend suite was not rerun on this head. The 3686/3686 result is from `486e44c` (ALV-016-C01 R02, independently approved). The product code under test is identical to that commit (the diff since is documentation, handoff and review records and the Gate C tooling); the Gate C tooling tests were run on this head. The reviewer may require a fresh full run.
- **Signed-but-not-finalized note (C8).** A note that is signed but not yet finalized is protected by the service and API (a change is refused with a clinical error, asserted in the test), not by a database trigger: a direct UPDATE of that note at the persistence layer is not rejected. Once the encounter is finalized the database refuses it (`TR_EncounterNotes_FinalizedImmutable`). This is recorded in the evidence as an observation, not hidden, and was judged within C8's threshold ("rejected or routed through amendment/addendum") because the signed state is reachable only through the service. The reviewer may regard a database-level guard as desirable; that would be a new story, not a Gate C change.
- **C2 scope.** The strip is part of the patient header and so appears on every patient screen; the walkthrough proves it is on screen, carries the facts and sits above the work area on the planning/completion-review, prescribing, charting and diagnosis screens. It does not drive a completion or a prescription to its end with a flagged patient, and there is no blocking confirmation; the criterion's threshold is "alert visible at each gated point". The strip shows counts and a link, not the alert title; the title is on the details screen (`safety` walkthrough).
- **Completion has no screen of its own.** The completion review opens from the treatment-plan tab, so the C2 "planning" and "completion" checks share a route.
- **Tablet-width walkthroughs were not run.** No Gate C criterion names a tablet or responsive check (Gate B's B6 did); mocked Playwright includes a tablet project (136/136).
- **Screenshots are not in the package.** The walkthrough specs write screenshots; they were left out of the committed evidence to keep it text-only. The per-walkthrough JSON and run outputs are included.
- **`frontend/tsc.txt`.** `tsc --noEmit` prints nothing when it passes, so the file captured by the run was empty; after the evidence commit it was given a one-line statement of the exit code (0), which the run recorded in `REPOSITORY_STATE.md`.
- **Limits of the evidence.** Browser walkthroughs run against the Vite dev server proxying a real API; the C8 attempts are a defined set of statements per record class, not an exhaustive enumeration of every column.
