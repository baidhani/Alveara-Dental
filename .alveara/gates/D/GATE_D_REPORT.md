## Disclosures

- **D5 had no single predeclared check.** The criterion's method is "automated duplicate-submission + concurrent-edit test"; the repository had many such tests spread across classes but no single named one. The tooling above is a Gate-level addition, written before the evaluation, that changes no product control. Its harness repeats the Gate C one (`GateCHistoryIntegrityTests`, approved and left unchanged). The reviewer may judge whether the tooling together with the existing tests satisfies the threshold ("duplicate submission rejected/idempotent; concurrent stale edit detected, not silently applied").
- **Two first-run problems in the D5 tooling were fixed before the evaluation:** two attacks had been "rejected" by SQL type errors (206, 245) rather than a control, and a stale-reversal case had been refused for a different reason (`payment_refunded`). The tooling now requires a custom trigger error for every required rejection and asserts the conflict type for every stale case.
- **A completion submitted twice with different items under one key** is refused as a `TreatmentPlanException` (no billing code); the evidence records the exception type.
- **D4 is an inspection plus a walkthrough**, as predeclared; it does not and cannot prove the absence of a dose claim in every possible state of every screen. The no-claim statements are asserted in panel tests and the banner is checked in the walkthrough.
- **Tablet-width walkthroughs were not run.** No Gate D criterion names a tablet or responsive check; mocked Playwright includes a tablet project (136/136).
- **Screenshots are not in the committed evidence** (text-only); the per-walkthrough JSON and run outputs are included.
- **Limits of the evidence.** Browser walkthroughs run against the Vite dev server proxying a real API; the D5 attempts are a defined set of statements per record class, not an exhaustive enumeration of every column.
